# 第 5 回 復習の設計と、テストしにくい作り

> 所要時間の目安: 2 時間 / 前提: 第 1〜4 回

## この回のゴール

- **固定間隔の復習**(1・3・7 日)の動きを説明できる。
- 復習の処理が**テストしにくい**理由と、直し方を説明できる。
- 保存されたデータ・取り込むデータを**疑う**書き方を説明できる。

## 1. 固定間隔の復習(`review-store.ts`)

章末クイズで**間違えた問題**を、思い出す頃に再出題する。

| 段階(`stage`) | 次の出題 | 意味 |
|---|---|---|
| 0 | 1 日後 | 間違えた直後 |
| 1 | 3 日後 | 次に正解した |
| 2 | 7 日後 | さらに正解した |
| 3 に届く | (卒業。記録を削除) | 3 回続けて思い出せた |

- **不正解** → 段階 0 に戻る(1 日後)。**正解**は、**すでに復習中の問題だけ**段階を進める(最初から正解の問題は、記録しない)。
- 間隔は**固定**で、効果を確かめてから FSRS などへ置き換える前提(コードのコメントにも明記)。
- 記録のキーは `章の id#問題の番号`。**章の中で問題の順序を変えると、記録がずれる**(→ [学習資料 6](../learn/06-troubleshooting-maintenance.md))。

## 2. 疑う: 取り込みの検査

JSON の書き出し・読み込みで、別の端末へ移せる。読み込みは、**形式を全部検査**し、1 つでも合わなければ**何も変更しない**。

- `entryId` は空でない文字列・`questionIndex` は 0 以上の整数・`stage` は 0〜(間隔の数 − 1)・`dueAt` は有限の数。
- 同じ問題は、**期限が後の方**を残す。

## 3. テストしにくい作り

この復習の処理には、**自動テストがありません**。理由は、**計算が、ブラウザの部品と一体**になっているからです。

- **`localStorage` と `window` を直接**呼ぶので、Node では動かない(`ReferenceError`)。
- 「次の段階・次の期限を決める計算」が、保存・通知と**同じ関数の中**にある。

**直し方**(ColorEncyclopedia の `spaced-repetition.ts` が見本): 計算を**純粋関数**(状態と答えと時刻を受け取り、新しい状態を返す)に**切り出し**、保存と通知は薄い殻にする。純粋関数は Node で、**時刻を渡して**テストできる(`now` 引数は、すでにその準備になっている)。

> 学び: **テストしやすさは、設計で決まる**。「計算」と「外の世界(保存・画面・時刻)」を分ける。

## 4. 総合演習

1. 第 1 回の検査に、「全章の `operationSteps` が **3 個以上**」を足してください(結果を見て、それが守るべきことか考える)。
2. 第 2 回の `loop` の問題を直す**案**を書いてください。直したあと、**どの章の結果が変わるか**を、全章に `resolveScene` を当てて前後で比べる手順も書いてください。
3. `recordAnswer` を、純粋関数 `nextRecord(existing, correct, now)` に切り出す**設計**を書いてください(入力・出力・テストで確かめる性質)。

## 確認問題

1. 不正解のあと、次の出題はいつですか。
2. 復習の処理を Node でテストできないのは、なぜですか。
3. 取り込みで、1 件でも形式が合わないとき、何をしますか。

## 解答

1. 1 日後(段階 0 に戻る)。
2. `localStorage` と `window` を直接呼んでいて、計算が保存・通知と一体だから。
3. **何も変更しない**(失敗を返す)。

## まとめ

- 復習は**固定間隔**(1・3・7 日)。取り込みは**全部検査**して、合わなければ何もしない。
- **計算を純粋関数に切り出す**と、テストできる。
