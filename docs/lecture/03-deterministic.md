# 第 3 回 乱数なしで作る(決定論的な生成)

> 所要時間の目安: 2 時間 / 前提: 第 2 回

## この回のゴール

- **乱数も時刻も使わない**ことが、サーバー描画に必要な理由を説明できる。
- 「先に予想」の問いと選択肢を、**決まった式**で作る方法を説明できる。
- ASCII の結晶が、**距離と角度だけ**で描かれる仕組みを説明できる。

## 1. なぜ決定論的か

このサイトは、Next.js で**サーバー側で一度描いて**、ブラウザで**もう一度**描きます(ハイドレーション)。**2 回の結果が違う**と、画面がちらつき、警告が出ます。乱数(`Math.random`)や現在時刻を使うと、2 回の結果が**必ず違う**。

> 装飾や選択肢を作る関数は、**同じ入力から、いつも同じ出力**にする(純粋関数)。

## 2. 先に予想(`guess.ts`)

手順の再生中に、「次の手順はどれ?」と問う(任意・既定はオフ・採点も記録もしない)。**問いすぎない**ために、1 回の再生で問うのは**最大 3 か所**。

```javascript
// 実行できる
(async () => {
  const g = await import("./src/lib/guess.ts");

  console.log("問う遷移の番号(手順の数 → 番号)");
  for (const n of [2, 3, 4, 6, 10]) console.log(" ", n, JSON.stringify(g.guessTransitions(n)));

  const a = g.guessChoices(6, 2);
  const b = g.guessChoices(6, 2);
  console.log("選択肢(手順 2 の次を問う):", JSON.stringify(a));
  console.log("もう一度作っても同じ(乱数なし):", JSON.stringify(a) === JSON.stringify(b));
  console.log("正解の位置の手順 = 次の手順(3):", a.indices[a.correct]);
  // 正解の位置は、手順によって動く(いつも先頭ではない)
  console.log("正解の位置の例:", [0, 1, 2, 3, 4].map((i) => g.guessChoices(6, i).correct).join(","));
})();
```

```text
# 出力
問う遷移の番号(手順の数 → 番号)
  2 []
  3 [0,1]
  4 [0,1,2]
  6 [0,2,4]
  10 [0,4,8]
選択肢(手順 2 の次を問う): {"indices":[1,3,0],"correct":1}
もう一度作っても同じ(乱数なし): true
正解の位置の手順 = 次の手順(3): 3
正解の位置の例: 0,2,1,0,2
```

- 手順が **3 つ未満**なら問わない(遷移が 2 つ未満)。多いときは、**等間隔に 3 か所**を選ぶ。
- 選択肢 = **正解(次の手順)+ 別の手順 2 つ**。別の手順の選び方と、並びのずらし方は、**`stepIndex` から計算**する(再読込しても同じ)。**正解の位置が毎回同じにならない**ように、ずらす。

## 3. ASCII の結晶(`ascii-crystal.ts`)

6 回対称の雪の結晶のような絵を、**文字だけ**で描く。考え方:

1. 中心からの**距離 r** と**角度 θ** を、60° の扇形に**折り返す**(対称にするため)。
2. **主枝**(中心から伸びる線)と、**側枝**(主枝から 60° で分かれる短い線)までの**距離**が近いほど、**濃い文字**(`" .:+*#@"`)。
3. 文字の縦横比は約 2:1 なので、**縦を 2 倍**に伸ばして距離を測る。

```javascript
// 実行できる
(async () => {
  const { asciiCrystal } = await import("./src/lib/ascii-crystal.ts");
  const small = asciiCrystal(21, 11);
  console.log(small);
  console.log("何度作っても同じ:", small === asciiCrystal(21, 11));
  const rows = small.split("\n");
  const flip = (s) => s.split("").reverse().join("");
  console.log("上下対称:", rows.every((row, i) => row === rows[rows.length - 1 - i]));
  console.log("標準の大きさ(49 x 25)の行数:", asciiCrystal().split("\n").length);
})();
```

- 出す場所は、**ヒーロー・検索結果なしの表示・404 だけ**(本文や操作部品には出さない)。色は既存の青のトークンだけ。
- 乱数も時刻も使わないので、**サーバーでもブラウザでも、必ず同じ形**。

## 確認問題

1. 装飾や選択肢に `Math.random` を使うと、何が起きますか。
2. 「先に予想」で、1 回の再生に問う数を 3 か所までにするのは、なぜですか。
3. ASCII の結晶で、縦を 2 倍にして距離を測るのは、なぜですか。

## 解答

1. サーバー描画とブラウザ描画の結果が食い違い、ちらつきや警告が出る。
2. 問いすぎると「試された」感が出て、学習の流れを邪魔するから。
3. 文字の縦横比がおよそ 2:1 で、そのままだと縦に潰れた形になるから。

- 選択肢の並びも、**入力から決まる式**で作る。
