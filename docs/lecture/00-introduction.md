# 第 0 回 全体の見取り図

> 所要時間の目安: 1 時間 / 前提: HTML・TypeScript の基本

## この回のゴール

- 章(Markdown)が、**図・クイズ・復習**になるまでの流れを説明できる。
- 「**章のデータ**」と「**見せ方の規則**」を分けてある理由を説明できる。
- 保存先が**ブラウザの中だけ**であることの意味を説明できる。

## 1. 流れ

![構成図](../diagrams/architecture.svg)

1. **章**: `content/foundations/<id>.md`。frontmatter に、名前・分類・**手順**(`operationSteps`)・**クイズ**(`quiz`)・ガイド(`guide`)・主張(`claim`)。
2. **ローダー**: frontmatter と本文を読む(静的生成のときに 1 回)。
3. **図の型**(`step-scene.ts`): 章の **id** から、「平面か立体か」「流れか輪か」を、**規則表**で決める。
4. **手順の図**: 平面は SVG、立体は three.js(「立体」を選んだときだけ読み込む)。
5. **復習**: 章末クイズで間違えた問題を、1・3・7 日後に再出題。記録は**localStorage**。

## 2. データと規則を分ける

| 何を | どこに |
|---|---|
| 章の内容(説明・手順・クイズ) | Markdown(**書く人が触る**) |
| 見せ方の規則(どの図にするか・どのアイコンか) | `src/lib/step-scene.ts` の**規則表**(**コードで直す**) |

章を足すだけなら、規則表は触らなくてよい(id から**自動で**決まる)。**規則に当たらない章は、既定の図**になる。

## 3. 保存先はブラウザの中だけ

サーバーも DB もありません。復習の記録・「平面 / 立体」の好み・「先に予想」の設定は、**端末のブラウザ**にだけ保存されます。**端末を変えると引き継がれません**(復習は JSON の書き出し・読み込みで移せます)。

## 確認問題

1. 章を 1 つ足すとき、`step-scene.ts` を直す必要は、いつありますか。
2. 立体の図が、「立体」を選んだときだけ読み込まれるのは、なぜ良いですか。
3. 復習の記録が、端末を変えると消えるのは、なぜですか。

## 解答

1. 規則で図の型が合わない章だけ(個別の上書き `OVERRIDES` を足す)。通常は不要。
2. 最初のページを軽くできる(three.js は大きいので、使わない人には読み込まない)。
3. サーバーに保存せず、ブラウザの localStorage にだけ持っているから。

## まとめ

- **章(データ)→ ローダー → 規則表で図の型 → 図・クイズ・復習**。
- データと規則を分ける。保存は端末の中だけ。
- 次の回は、**章のデータの形**。
