## 概要

パスワードを平文でデータベースに保存すると、情報が漏れたときに、すべてのパスワードが読まれてしまう。そこで、**元に戻せない形(ハッシュ値)**で保存する。さらに、ユーザーごとのランダムな値(**ソルト**)を加え、**計算に時間のかかる**パスワード用のハッシュ関数を使う。

## 基礎文法

| 用語 | 意味 |
| --- | --- |
| ハッシュ値 | 元のデータから計算した、固定長の値。元のデータには戻せない |
| ソルト | ユーザーごとに作るランダムな値。同じパスワードでも結果が変わる |
| ストレッチング | わざと計算に時間をかけて、総当たり攻撃を難しくする |

## つまずきやすい点

- SHA-256のような高速なハッシュ関数を、そのままパスワードに使わない。高速だと、総当たりで試されやすい。bcrypt・scrypt・Argon2のような、パスワード用の関数を使う
- ハッシュ化は暗号化とは違う。暗号化は鍵で元に戻せるが、ハッシュ化は元に戻せない
- ソルトは秘密にしなくてよい(ハッシュ値と一緒に保存する)。目的は、同じパスワードを見分けにくくし、事前に計算した表の攻撃を防ぐこと
- ハッシュ化したからといって、弱いパスワードが安全になるわけではない

## 実装例(コード)

```python
import bcrypt

hashed = bcrypt.hashpw(b"my-password", bcrypt.gensalt())  # ソルトは自動で含まれる
print(bcrypt.checkpw(b"my-password", hashed))  # True
```
