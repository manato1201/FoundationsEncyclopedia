## 概要

JavaScriptは基本的にシングルスレッドで動作するにもかかわらず、`setTimeout`やPromiseのような非同期処理を扱える。これを可能にしているのがイベントループで、「今すぐ実行するコード」と「後で実行すべきコールバック」をキューで管理し、メインスレッドが空いたタイミングで順次実行していく仕組み。

## 基礎文法

```javascript
console.log("1"); // 同期処理: 即座に実行

setTimeout(() => console.log("2"), 0); // マクロタスクキューへ

Promise.resolve().then(() => console.log("3")); // マイクロタスクキューへ

console.log("4"); // 同期処理: 即座に実行

// 出力順: 1, 4, 3, 2
```

- 同期コードが全て実行し終わった後、マイクロタスクキュー(Promise等)が優先的に処理され、その後にマクロタスクキュー(setTimeout等)が処理される

## つまずきやすい点

- `setTimeout(fn, 0)`は「0ミリ秒後に実行」を意味しない。あくまで「今の同期コードとマイクロタスクが全て終わった後、できるだけ早く」実行されるという意味で、正確なタイミングは保証されない
- マイクロタスク(Promiseのコールバック)が次々と新しいマイクロタスクを生成し続けると、マクロタスク(setTimeoutやUIの再描画等)がいつまでも実行されず、画面がフリーズしたように見える「マイクロタスクの飢餓状態」が起こりうる
- Node.jsのイベントループはブラウザのものと細部の実装が異なる(`process.nextTick`のような独自のキューを持つ)。「JavaScriptのイベントループ」と一括りにせず、実行環境ごとの違いを意識する必要がある場面もある

## 実装例(コード)

```javascript
async function example() {
  console.log("A");
  await Promise.resolve(); // ここで一旦制御を返す(マイクロタスクとしてキューイング)
  console.log("B"); // Aの後、他の同期処理が終わってから実行される
}
```
