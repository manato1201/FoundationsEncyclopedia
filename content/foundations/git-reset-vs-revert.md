## 概要

コミットを取り消す方法は2つある。**git reset**は、ブランチの位置を過去のコミットに戻すことで、履歴そのものを書き換える。**git revert**は、指定したコミットの変更を打ち消す**新しいコミット**を追加するので、履歴は残る。

## 基礎文法

| コマンド | 履歴 | 向く場面 |
| --- | --- | --- |
| `git reset` | 書き換わる(コミットが消えたように見える) | まだ共有していないローカルのコミット |
| `git revert` | そのまま残る(打ち消しのコミットが増える) | すでに共有したブランチ |

resetには、作業ツリーとステージの扱いが変わるモードがある。

| オプション | 意味 |
| --- | --- |
| `--soft` | コミットだけ戻す(変更はステージに残る) |
| `--mixed`(既定) | コミットとステージを戻す(変更は作業ツリーに残る) |
| `--hard` | 作業ツリーの変更も破棄する(未保存の変更が失われる) |

## つまずきやすい点

- `git reset --hard` は、コミットしていない変更も消える。実行前に、変更を保存してあるかを確認する
- 共有したブランチでresetすると、他の人の履歴と食い違い、強制pushが必要になる。共有後は、revertを使う
- 消えたように見えるコミットも、`git reflog` でしばらくは探して戻せることが多い

## 実装例(コード)

```bash
# 直前のコミットを、履歴を残したまま打ち消す
git revert HEAD

# ローカルだけの直前のコミットを取り消す(変更は作業ツリーに残す)
git reset --mixed HEAD~1
```
