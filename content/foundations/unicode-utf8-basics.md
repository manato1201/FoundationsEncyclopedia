## 概要

コンピューターが扱うのは数値だけなので、文字には番号を割り当てる必要がある。**Unicode**は、世界中の文字に一意の番号(コードポイント)を割り当てる規格。その番号をバイト列として保存・送信する方式が**符号化**で、現在のWebやソースコードでは**UTF-8**が標準的に使われている。

## 基礎文法

| 文字 | コードポイント | UTF-8のバイト数 |
| --- | --- | --- |
| A | U+0041 | 1 |
| é | U+00E9 | 2 |
| あ | U+3042 | 3 |
| 😀 | U+1F600 | 4 |

- UTF-8はASCIIと互換。英数字だけの文章は、ASCIIと同じバイト列になる
- Shift_JISなどは別の符号化で、同じ「あ」でもバイト列が違う(Shift_JISでは2バイト)
- ファイルの先頭に付く BOM(符号化の目印)は、UTF-8では必須ではなく、付いていると困るツールもある

## つまずきやすい点

- 「文字数」と「バイト数」は違う。文字数の制限(例: 140文字)と、保存先の容量制限(バイト)を取り違えない
- 見た目が1文字でも、複数のコードポイントでできていることがある(「é」を「e」と結合用のアクセントの2つで表すなど)。絵文字の組み合わせも同じ。文字数を数えるときは、使う言語の何が「長さ」になるかを確認する
- 文字化けの原因の多くは、書いた側と読む側の符号化の不一致。ファイル・データベース・HTTPヘッダー・HTMLの`<meta charset>`で、UTF-8に揃える
- WindowsのPowerShellやコマンドプロンプトの既定の文字コードは、環境や設定によって異なり、UTF-8でないことがある

## 実装例(コード)

```python
s = "Aあ😀"
print(len(s))                    # 3(文字数)
print(len(s.encode("utf-8")))    # 8(バイト数: 1 + 3 + 4)
print("あ".encode("utf-8").hex(" "))   # e3 81 82
print("あ".encode("shift_jis").hex(" ")) # 82 a0

# 符号化を取り違えて読むと、文字化けする
broken = "あ".encode("utf-8").decode("latin-1")
print([hex(ord(c)) for c in broken])  # ['0xe3', '0x81', '0x82'](3つの別の文字になる)
```
