## 概要

cronは、指定した時刻・周期でコマンドやスクリプトを自動的に実行するLinuxの標準的な仕組み。バックアップの取得、ログのローテーション、定期的なレポート生成など、「人手を介さず決まった時間に実行したい処理」を自動化するために広く使われている。

## 基礎文法

```bash
crontab -e   # cronの設定(crontab)を編集する
```

```
# 分 時 日 月 曜日 コマンド
0 3 * * * /path/to/backup.sh          # 毎日午前3時に実行
*/5 * * * * /path/to/healthcheck.sh    # 5分ごとに実行
0 0 1 * * /path/to/monthly_report.sh   # 毎月1日の午前0時に実行
```

各フィールドは「分・時・日・月・曜日」の順で、`*`は「全ての値」を意味する。

## つまずきやすい点

- cronジョブはデフォルトでは対話的なシェル環境とは異なる、限定された環境変数で実行される。ローカルのターミナルでは動くスクリプトが、cron経由で実行すると「コマンドが見つからない」エラーになることがある(`PATH`環境変数の違いが典型的な原因)
- cronの実行結果(標準出力・エラー出力)は、デフォルトでは画面に表示されず、設定によってはメールで通知されたり、単に破棄されたりする。ログをファイルへリダイレクトしておかないと、ジョブが失敗していても気づけないことがある
- サーバーのタイムゾーン設定によって、意図した時刻と実際の実行時刻がずれることがある。特に複数のサーバーやクラウドサービスをまたいで運用する場合、タイムゾーンの統一(UTCに揃える等)を意識しておくとトラブルを避けやすい

## 実装例(コード)

```bash
# 実行結果をログファイルへ記録する例
0 3 * * * /path/to/backup.sh >> /var/log/backup.log 2>&1
```
