## 概要

テストは、確かめる範囲で呼び分ける。**単体テスト**は、関数やクラスなど小さな単位を、ほかから切り離して確かめる。**結合テスト**は、複数の部品や、データベース・外部サービスなどをつなげた状態で確かめる。

## 基礎文法

| 項目 | 単体テスト | 結合テスト |
| --- | --- | --- |
| 範囲 | 小さい(1つの関数やクラス) | 広い(複数の部品・外部の仕組み) |
| 実行の速さ | 速い | 遅くなりやすい |
| 見つけやすい問題 | 部品の中のロジックの誤り | 部品どうしの受け渡し、設定の誤り |

## つまずきやすい点

- どちらか一方では足りない。単体テストが通っても、部品をつなぐと動かないことがあり、結合テストだけでは、原因の場所を絞りにくい
- ダミー(モック)に頼りすぎると、実際の挙動とずれたテストになる。重要なつながりは、結合テストで確かめる
- 結合テストは遅くて壊れやすくなりがち。数を絞り、重要な流れに集中させる

## 実装例(コード)

```python
# 単体テスト: 計算ロジックだけを確かめる
def test_total_price():
    assert total_price([100, 200], tax_rate=0.1) == 330

# 結合テスト: 実際のデータベースを使って、保存と取得がつながるかを確かめる
def test_save_and_load_order(db):
    save_order(db, order_id=1, items=[100, 200])
    assert load_order(db, 1).total == 300
```
