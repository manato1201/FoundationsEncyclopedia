## 概要

CI(継続的インテグレーション)パイプラインは、コードの変更がリポジトリにpushされるたびに、ビルド・テスト・(必要なら)デプロイを自動実行する仕組み。手動での確認漏れを減らし、変更を早い段階で検証できるようにする。

## 基礎文法

典型的なパイプラインのステージ構成:

1. **チェックアウト**: リポジトリの最新コードを取得する
2. **依存関係のインストール**: `npm install`のようなパッケージ取得
3. **Lint/型チェック**: `eslint`・`tsc --noEmit`のような静的検査
4. **テスト**: 単体テスト・結合テストの実行
5. **ビルド**: `next build`のような本番用ビルド
6. **デプロイ(任意)**: ビルド成果物を実際の環境へ配置

## つまずきやすい点

- ローカルでは通るのにCI上だけ失敗する場合、Node.jsのバージョン差・環境変数の未設定・OS依存のパス区切り文字の違いなど、実行環境の差異が原因であることが多い
- テストが不安定(flaky)な状態を放置すると、失敗が「本当のバグ」なのか「たまたま落ちただけ」なのか区別できなくなり、CIへの信頼が失われていく
- パイプラインの各ステージを並列化・キャッシュ化せずに全て直列実行すると、変更のたびに待たされる時間が長くなり開発体験を損なう

## 実装例(コード)

```yaml
# .github/workflows/ci.yml の簡略例
jobs:
  build:
    steps:
      - uses: actions/checkout@v4
      - run: npm install
      - run: npm run lint
      - run: npx tsc --noEmit
      - run: npm run build
```
