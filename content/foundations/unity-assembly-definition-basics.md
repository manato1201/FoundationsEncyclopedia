## 概要

Unityでは、何も設定しないと、プロジェクトのスクリプトがまとめてコンパイルされる。**Assembly Definition**(`.asmdef`)を使うと、スクリプトを**アセンブリ**というまとまりに分けられる。変更したときに再コンパイルされる範囲が小さくなり、待ち時間を減らせる。

## 基礎文法

| 要素             | 役割                                                |
| ---------------- | --------------------------------------------------- |
| `.asmdef`        | そのフォルダ以下のスクリプトを、1つのまとまりにする |
| 参照(References) | そのまとまりが使う、ほかのまとまり                  |
| Editor専用の指定 | エディタ専用のスクリプトを、ビルドから分ける        |

## つまずきやすい点

- 別のアセンブリのクラスを使うには、参照の設定が要る。設定がないと、「型が見つからない」というエラーになる
- 参照は一方向にする。循環するとコンパイルできないので、共通の部分を、別のアセンブリに分ける
- まとまりを細かく分けすぎると、管理が大変になる。再コンパイルの待ち時間が問題になってから、導入しても遅くない

## 実装例(コード)

```json
{
  "name": "MyGame.Gameplay",
  "references": ["MyGame.Core"],
  "includePlatforms": []
}
```
