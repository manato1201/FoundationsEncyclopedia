## 概要

HTTPのメソッドやステータスコード、ヘッダーの意味([HTTPリクエスト/レスポンスの基礎](/foundations/http-request-response-basics))は、HTTP/1.1・HTTP/2・HTTP/3のどれでも同じ。違うのは、**データを回線に乗せる運び方**。ページには画像・CSS・スクリプトなど多数のファイルが含まれるため、運び方の効率が表示速度に効く。

## 基礎文法

| 版 | 土台 | 特徴 |
| --- | --- | --- |
| HTTP/1.1 | TCP | 1接続で1つずつ処理する。接続を複数開いて並行させる |
| HTTP/2 | TCP | 1接続で多重化、ヘッダー圧縮、バイナリ形式 |
| HTTP/3 | QUIC(UDP) | ストリームごとに再送、接続の確立が速い、暗号化が必須 |

- HTTP/2・HTTP/3は、ブラウザではHTTPS(暗号化)での利用が前提になっている
- 利用する版は、ブラウザとサーバーが自動で選ぶので、アプリのコードを書き換える必要は、通常ない

## つまずきやすい点

- HTTP/2・HTTP/3は、サーバーやCDNが対応して初めて使える。クライアントだけ新しくしても、サーバーが古ければ HTTP/1.1 になる
- HTTP/2は「多重化されるから速い」が、パケットの損失が多い回線では、TCP全体の待ちが響き、差が縮むことがある。この弱点が、HTTP/3の動機の1つ
- HTTP/3は UDP を通すため、一部の企業ネットワークでは、UDPが制限されて使えない。その場合は、自動的にHTTP/2へ戻る
- 実際にどの版で通信したかは、ブラウザの開発者ツールのネットワーク欄(プロトコルの列)か、curlで確かめられる

## 実装例(コード)

```bash
# 使われた HTTP の版を表示する(例: 2)
curl -s -o /dev/null -w "%{http_version}\n" https://example.com

# HTTP/2 を明示的に指定して、レスポンスヘッダーを見る
curl -sI --http2 https://example.com
```
