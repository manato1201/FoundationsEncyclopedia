## 概要

複数の処理が同じデータを同時に更新すると、片方の更新が失われることがある。これを防ぐ方法が、**悲観的ロック**と**楽観的ロック**。前者は「衝突が起きるものとして」先にロックをかけ、後者は「あまり起きないものとして」、更新時に衝突を確認する。

## 基礎文法

| 方式 | 考え方 | 向く場面 |
| --- | --- | --- |
| 悲観的ロック | 先にロックして、ほかを待たせる | 衝突が多い・失敗が許されない |
| 楽観的ロック | 更新時に衝突を確認する | 衝突が少ない・待たせたくない |

## つまずきやすい点

- 悲観的ロックは、長く保持すると、ほかの処理が待たされる。ロックの時間を短くする
- 複数のロックを違う順序で取ると、デッドロックになる場合がある
- 楽観的ロックは、衝突したときに、やり直す処理を用意する必要がある

## 実装例(コード)

```sql
-- 悲観的ロック: 読むときに行をロックする
SELECT * FROM accounts WHERE id = 1 FOR UPDATE;

-- 楽観的ロック: バージョンが同じときだけ更新する
UPDATE accounts SET balance = 900, version = version + 1
WHERE id = 1 AND version = 3;
```
