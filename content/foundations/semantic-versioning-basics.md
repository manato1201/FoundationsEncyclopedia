## 概要

セマンティックバージョニング(SemVer)は、`1.4.2`のような`MAJOR.MINOR.PATCH`の3部構成でバージョン番号を管理する規約。それぞれの数値の増加が「どんな変更が含まれるか」を意味的に表現するため、利用者はバージョン番号を見ただけで更新の影響範囲を予測できる。

## 基礎文法

- **MAJOR**: 後方互換性を壊す変更(既存の使い方が動かなくなる可能性がある)
- **MINOR**: 後方互換性を保ったまま機能を追加した変更
- **PATCH**: 後方互換性を保ったままバグ修正のみを行った変更

```json
{
  "dependencies": {
    "next": "16.2.10", // 完全一致(このバージョンに固定)
    "react": "^19.2.4", // MAJORが変わらない範囲での自動更新を許可
    "eslint": "~9.0.0" // PATCHの範囲での自動更新のみを許可
  }
}
```

## つまずきやすい点

- SemVerは「規約」であり、パッケージの作者が正しく守っているとは限らない。MINORバージョンの更新のつもりが実は破壊的変更を含んでいた、という事故は珍しくなく、`package-lock.json`のようなロックファイルで実際にインストールされるバージョンを固定しておくことが重要になる
- `^`(キャレット)と`~`(チルダ)の意味の違いを混同しやすい。`^19.2.4`はメジャーバージョンが変わらない範囲(`19.x.x`)、`~9.0.0`はマイナーバージョンが変わらない範囲(`9.0.x`)を許容するという違いがある
- 0.x.x系(メジャーバージョンが0)のパッケージは、SemVerの慣習上「まだ安定版に達していない」という扱いになり、MINORバージョンの更新でも破壊的変更が入ることが許容されている

## 実装例(コード)

```bash
# npmでSemVerに沿ったバージョンを上げるコマンド
npm version patch   # 1.4.2 -> 1.4.3
npm version minor    # 1.4.2 -> 1.5.0
npm version major    # 1.4.2 -> 2.0.0
```
