## 概要

アセットパイプラインは、Maya/Blender等のDCCツールで作成したモデル・テクスチャ・アニメーションを、ゲームエンジンが実際に読み込める最適化された形式へ変換する一連の工程。[コンテナイメージのレイヤー構造](/foundations/container-image-layers)のビルドパイプラインと同様に、「元データ→中間処理→最終成果物」という変換の流れを持つ。

## 基礎文法

典型的なアセットパイプラインの流れ:

```
DCCツールでの作成(Maya/Blender)
  → エクスポート(FBX、glTF等の中間フォーマット)
  → インポート設定(圧縮、LOD生成等)
  → エンジン内部フォーマットへの変換
  → 実行時の読み込み
```

## つまずきやすい点

- DCCツールごとに座標系(Y-upかZ-upか等)や単位(メートルかセンチメートルか)が異なることがあり、エクスポート時にこれらの変換設定を誤ると、インポート後にモデルが横倒しになったり、極端に大きい/小さいサイズになったりする
- アセットのインポート設定(圧縮率、ミップマップの有無等)を、素材ごとの用途を考えずに一律で適用すると、必要以上に画質が劣化したり、逆に不要に容量が増えたりする。UIのアイコンと背景の風景テクスチャでは、求められる設定が異なることが多い
- パイプラインの各段階を手作業で行っていると、素材数が増えるにつれて更新作業が煩雑になる。自動化スクリプトや、変更を検知して自動的に再インポートする仕組み([CIパイプラインの基本ステージ](/foundations/ci-pipeline-basics)と同様の自動化の発想)を整備することが、中〜大規模なプロジェクトでは重要になる
