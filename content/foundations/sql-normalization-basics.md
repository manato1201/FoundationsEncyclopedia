## 概要

正規化(normalization)は、リレーショナルデータベースのテーブル設計において、データの重複を排除し、更新時の不整合(同じデータが複数箇所にあり片方だけ更新されてしまう問題)を防ぐための段階的な設計手法。第1正規形から第3正規形まで、代表的な基準が広く知られている。

## 基礎文法

正規化前(重複あり):

```
| order_id | user_name | user_email      | product |
|----------|-----------|------------------|---------|
| 1        | Alice     | alice@x.com      | Sword   |
| 2        | Alice     | alice@x.com      | Shield  |
```

正規化後(usersテーブルとordersテーブルに分割):

```
users:  id, name, email
orders: id, user_id, product
```

同じユーザーの名前・メールアドレスが複数行に重複しなくなり、更新は`users`テーブルの1行を直すだけで済む。

## つまずきやすい点

- 正規化を進めすぎる(テーブルを細かく分割しすぎる)と、データを取り出す際に多数の[JOIN](/foundations/sql-joins-basics)が必要になり、クエリが複雑化しパフォーマンスが低下することがある。読み取り性能を優先してあえて重複を許す「非正規化」を行うこともある
- 「正規化されているかどうか」は形式的なルールだけでなく、実際のデータの使われ方(更新頻度、読み取りパターン)を踏まえて判断する必要がある。教科書的な正規形を機械的に適用するだけでは最適な設計にならないことがある
- 正規化はリレーショナルデータベース特有の考え方であり、NoSQLデータベース(ドキュメント指向DB等)では、むしろ意図的にデータを重複させて読み取りを高速化する設計が好まれることが多い

## 実装例(コード)

```sql
-- 非正規化の例: レポート用に集計済みの列をあえて重複して持たせる
ALTER TABLE users ADD COLUMN total_orders INT DEFAULT 0;
-- 注文が発生するたびにこのカラムを更新するトレードオフを受け入れる
```
