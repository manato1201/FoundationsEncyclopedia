## 概要

Big-O記法は、アルゴリズムの処理時間やメモリ使用量が入力サイズ`n`の増加に対してどのように増えていくかを表す記法。「何秒かかるか」という実測値ではなく、「nを2倍にしたら何倍になるか」という増加の傾向を表す点が重要。

## 基礎文法

代表的な計算量(増加が緩やかな順):

- `O(1)`: 定数時間。入力サイズに関係なく一定
- `O(log n)`: 対数時間。二分探索など、毎回選択肢が半分になる処理
- `O(n)`: 線形時間。配列を1回だけ全走査する処理
- `O(n log n)`: 準線形時間。多くの高速なソートアルゴリズム
- `O(n²)`: 二乗時間。二重ループで全ペアを比較する処理
- `O(2^n)`: 指数時間。全部分集合を試すような総当たり

## つまずきやすい点

- 「O(n²)は常にO(n log n)より遅い」と早合点しがちだが、これは`n`が十分大きいときの漸近的な傾向であり、`n`が小さい場合は定数倍の影響でO(n²)の方が速いこともある
- Big-Oは「最悪の場合」を指すことが多いが、平均計算量や償却計算量(amortized)と混同すると、実際の性能予測を誤る
- 計算量が同じでも、キャッシュ効率や定数倍の違いで実測速度は大きく変わりうる(CPUキャッシュとメモリ階層の基礎も参照)

## 実装例(コード)

```python
# O(n): 1回の走査で最大値を探す
def find_max(arr: list[int]) -> int:
    best = arr[0]
    for x in arr:
        if x > best:
            best = x
    return best

# O(n^2): 二重ループで全ペアの和がtargetに一致するか調べる(素朴な実装)
def has_pair_sum(arr: list[int], target: int) -> bool:
    for i in range(len(arr)):
        for j in range(i + 1, len(arr)):
            if arr[i] + arr[j] == target:
                return True
    return False
```
