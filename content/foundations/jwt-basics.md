## 概要

JWT(JSON Web Token)は、ユーザーの情報などを入れたデータに**署名**を付けたもの。ログイン後に発行し、以降のリクエストで送ってもらうことで、サーバーが毎回データベースを調べなくても、本人であることを確かめやすくなる。

## 基礎文法

JWTは、ドット(`.`)で区切られた3つの部分からできている。

| 部分 | 内容 |
| --- | --- |
| ヘッダー | 署名のアルゴリズムなど |
| ペイロード | ユーザーID、有効期限(exp)などの情報 |
| 署名 | ヘッダーとペイロードから計算した、改ざん検知用の値 |

## つまずきやすい点

- ペイロードは暗号化されていない。**誰でも読めるので、パスワードなどの秘密の情報は入れない**
- 一度発行したJWTは、有効期限まで有効になりやすい。盗まれたときに備えて、有効期限を短くする、更新の仕組みを用意する、といった対策を考える
- 署名の検証は、サーバーが正しい鍵で必ず行う。「アルゴリズムなし」を受け入れる実装などは危険なので、ライブラリの推奨設定に従う
- 保存場所(ブラウザのどこに置くか)でも、安全性が変わる。用途に合わせて選ぶ

## 実装例(コード)

```python
import jwt  # PyJWT

token = jwt.encode({"sub": "user-1", "exp": 1893456000}, "secret-key", algorithm="HS256")
data = jwt.decode(token, "secret-key", algorithms=["HS256"])  # 署名と期限を検証する
```
