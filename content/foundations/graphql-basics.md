## 概要

**GraphQL**は、APIのクエリ言語。クライアントが「どの項目がほしいか」を指定して、**1回のリクエスト**で必要なデータをまとめて取得できる。RESTでは、画面に必要なデータの取得に、複数のURLを呼ぶ必要が生じやすいが、GraphQLでは1回で済む。

## 基礎文法

| 比較 | REST | GraphQL |
| --- | --- | --- |
| 入口 | リソースごとのURL | 通常は1つのURL |
| 取得する項目 | サーバー側で決まる | クライアントが指定する |
| 型の定義 | 別途(OpenAPIなど) | スキーマが標準で持つ |

## つまずきやすい点

- クライアントが自由にクエリを書けるため、重いクエリで、サーバーに負荷をかけられる場合がある。深さや量の制限を考える
- キャッシュは、URLごとに行うRESTより、工夫が必要になる
- すべてのAPIをGraphQLにする必要はない。用途に合うほうを選ぶ

## 実装例(コード)

```graphql
query {
  user(id: 1) {
    name
    posts {
      title
    }
  }
}
```
