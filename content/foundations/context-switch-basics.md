## 概要

1つのCPUコアは、同時には1つの処理しか実行できない。それでも多くの処理が同時に動いて見えるのは、OSが短い時間ごとに実行する処理を切り替えているから。この切り替えで、状態を保存して復元する処理を**コンテキストスイッチ**と呼ぶ。

## 基礎文法

| 用語 | 意味 |
| --- | --- |
| コンテキスト | 処理の途中の状態(レジスタの値など) |
| タイムスライス | 1回の実行に割り当てる時間 |
| オーバーヘッド | 切り替え自体にかかる時間 |

## つまずきやすい点

- 切り替えには時間がかかる。頻繁に切り替わると、本来の処理に使える時間が減る
- スレッドの切り替えは、プロセスの切り替えより軽い。同じアドレス空間を共有できるため
- スレッドの数を増やしすぎると、切り替えのコストで、かえって遅くなる場合がある

## 実装例(コード)

```bash
# Linuxで、プロセスごとのコンテキストスイッチの回数を見る
grep ctxt /proc/self/status
```
