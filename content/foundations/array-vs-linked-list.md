## 概要

配列は要素をメモリ上に連続して並べるデータ構造で、連結リストは各要素(ノード)が次の要素へのポインタを持つことで繋がっているデータ構造。この違いが、ランダムアクセスと挿入・削除のパフォーマンス特性を正反対にする。

## 基礎文法

- **配列**: `array[5]`のようにインデックスを指定すれば、先頭アドレス+オフセットの計算だけで即座にアクセスできる([O(1)](/foundations/big-o-basics))。一方、途中への挿入・削除は、それより後ろの要素を全てずらす必要があり[O(n)](/foundations/big-o-basics)かかる
- **連結リスト**: 先頭から順にポインタを辿らないと目的の要素にたどり着けない(O(n)のアクセス)。一方、挿入・削除は前後のポインタを繋ぎ替えるだけで済み、その位置さえ分かっていればO(1)で行える

## つまずきやすい点

- 「連結リストは挿入・削除が速い」という理論上の性質だけを見て安易に採用すると、実際の性能では配列(可変長配列、C#の`List<T>`やC++の`std::vector`)の方が速いことが多い。連結リストは各ノードがメモリ上に散らばっているためキャッシュ効率が悪く、現代のCPUではこの影響が計算量以上に大きいことがある([CPUキャッシュとメモリ階層の基礎](/foundations/cpu-memory-basics)参照)
- 可変長配列(`ArrayList`等)は、容量を超えて要素を追加する際に内部で新しい大きな配列を確保してコピーする「再確保」が発生する。この操作自体はO(n)だが、頻度が低いため平均するとO(1)とみなせる(償却計算量)
- 「挿入・削除が本当に頻繁に、しかも先頭や中間で発生する」という具体的な使用パターンが明確な場合に限り、連結リストの利点が活きる。そうでない場合はまず配列ベースの構造を検討するのが実務的

## 実装例(コード)

```python
# 配列(リスト)の中間への挿入はO(n): 後ろの要素が全てずれる
arr = [1, 2, 4, 5]
arr.insert(2, 3)  # [1, 2, 3, 4, 5]
```
