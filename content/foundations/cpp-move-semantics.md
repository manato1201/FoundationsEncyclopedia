category: プログラミング言語
subcategory: C++

---

## 概要

ムーブセマンティクスは、一時オブジェクト(もう使われないことが分かっている値)からリソース(ヒープ上のメモリ等)を「コピーではなく移動」して受け渡す仕組み。`std::vector`のような大きなデータを持つオブジェクトを関数から返す際、従来はコピーが発生していたが、ムーブによりポインタの付け替えだけで済むようになる。

## 基礎文法

```cpp
std::vector<int> createLargeVector() {
    std::vector<int> v(1'000'000, 0);
    return v; // ムーブされる(C++11以降、コピー省略が働くことも多い)
}

std::vector<int> a = createLargeVector(); // コピーではなくムーブ
std::vector<int> b = std::move(a);        // 明示的にムーブ。以後aは「有効だが未規定の状態」
```

- `std::move`は実際には何も移動しない。対象を「ムーブ可能な右辺値」として扱うようキャストするだけで、実際のムーブ処理はムーブコンストラクタ/ムーブ代入演算子が行う

## つまずきやすい点

- `std::move`した後の元のオブジェクト(上記の`a`)は「有効だが未規定の状態」になる。ムーブ後に元のオブジェクトの中身を読み取って使おうとすると、意図しない値になっていることがある
- 自作クラスがムーブコンストラクタ/ムーブ代入演算子を定義していない場合、コンパイラが自動生成する条件(デストラクタやコピーコンストラクタを自前定義していない等)を満たさないと、ムーブのはずがコピーにフォールバックしてしまう
- 小さな値型(`int`等)には`std::move`を使ってもメリットがない。コピーとムーブのコストが変わらないため、意味のある最適化にならない

## 実装例(コード)

```cpp
class Buffer {
public:
    Buffer(Buffer&& other) noexcept : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr; // 元のオブジェクトを安全な状態にする
        other.size_ = 0;
    }
private:
    int* data_;
    size_t size_;
};
```
