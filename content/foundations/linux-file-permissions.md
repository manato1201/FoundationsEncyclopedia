## 概要

Linuxのファイルパーミッションは、各ファイル・ディレクトリに対して「誰が」「何をできるか」を細かく制御する仕組み。「所有者(owner)」「グループ(group)」「その他(other)」という3つの主体それぞれに、読み取り(r)・書き込み(w)・実行(x)の権限を個別に設定できる。

## 基礎文法

```bash
ls -l script.sh
# -rwxr-xr-- 1 alice staff 1234 Aug 19 10:00 script.sh
#  所有者(rwx) グループ(r-x) その他(r--)

chmod 750 script.sh   # 所有者:rwx(7)、グループ:r-x(5)、その他:なし(0)
chmod u+x script.sh   # 所有者に実行権限を追加
```

- r(読み取り)=4、w(書き込み)=2、x(実行)=1。これらを足し合わせた数字(例: 7=4+2+1)で表現するのが`chmod`の数値表記

## つまずきやすい点

- ディレクトリに対する`x`(実行)権限は、「そのディレクトリの中に入れるか(cdできるか)」を意味する。ファイルの`x`(実行できるか)とは異なる意味を持つため、「読み取り権限があるのにディレクトリの中を見れない」という状況は、`x`権限の欠如が原因であることが多い
- `chmod 777`(全員に全権限)のような設定は、動かないエラーを一時的に解消する「とりあえずの対処」として使われがちだが、セキュリティ上望ましくない。実際にどの主体にどの権限が必要かを最小限で見極めるべき([最小権限の原則](/foundations/least-privilege-principle))
- 所有者(誰がファイルを所有しているか)とパーミッション(何ができるか)は別の概念。`chown`で所有者を変更しても、パーミッション自体は変わらない

## 実装例(コード)

```bash
chown alice:staff script.sh   # 所有者とグループを変更する
chmod +x script.sh             # 実行権限を追加する(誰に対してかを省略すると全員に付与)
```
