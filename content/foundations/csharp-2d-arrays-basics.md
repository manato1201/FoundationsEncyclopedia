## 概要

C#で2次元的なデータ(グリッド、マップ等)を表現する方法には、`int[,]`(多次元配列、矩形配列)と`int[][]`(配列の配列、ジャグ配列)の2種類がある。前者は全ての行が同じ長さの「四角い」配列、後者は各行が独立した配列で、行ごとに長さが異なってもよい「ギザギザ(jagged)」な配列。

## 基礎文法

```csharp
// 多次元配列(矩形配列): 全ての行が同じ長さ
int[,] grid = new int[3, 4]; // 3行4列
grid[0, 0] = 1;
grid[2, 3] = 99;

// ジャグ配列(配列の配列): 行ごとに長さが異なってもよい
int[][] jagged = new int[3][];
jagged[0] = new int[] { 1, 2 };
jagged[1] = new int[] { 1, 2, 3, 4 };
jagged[2] = new int[] { 1 };
```

## つまずきやすい点

- `int[,]`(カンマ区切り、多次元配列)と`int[][]`(角括弧の連続、ジャグ配列)は見た目が似ているが全く別の型であり、構文も内部のメモリレイアウトも異なる。地形やタイルマップのように「必ず矩形」なデータには多次元配列、行ごとに要素数が変わりうるデータにはジャグ配列が向く
- 多次元配列は要素へのアクセスが単一の連続したメモリブロックへの計算で済むため、一般的にジャグ配列よりキャッシュ効率が良い([CPUキャッシュとメモリ階層の基礎](/foundations/cpu-memory-basics)参照)。パフォーマンスが重要な大きなグリッドを扱う場合はこの違いを意識する価値がある
- 多次元配列の`GetLength(0)`(行数)と`GetLength(1)`(列数)を混同しやすい。`Length`プロパティは「全要素数」(行数×列数)を返す点にも注意が必要

## 実装例(コード)

```csharp
// 多次元配列を全走査する典型例
for (int row = 0; row < grid.GetLength(0); row++)
{
    for (int col = 0; col < grid.GetLength(1); col++)
    {
        Debug.Log(grid[row, col]);
    }
}
```
