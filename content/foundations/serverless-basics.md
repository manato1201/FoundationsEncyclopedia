## 概要

サーバーレス(Serverless)は、開発者がサーバーのプロビジョニングやスケーリングを意識することなく、コード(多くの場合は関数単位)をクラウドにデプロイして実行できる実行モデル。「サーバーがない」わけではなく、その管理をクラウド提供者が完全に肩代わりしてくれる、という意味合いが正確な理解に近い。

## 基礎文法

サーバーレス関数(AWS Lambda等)の典型的な特徴:

```javascript
// サーバーレス関数の例(Node.js)
exports.handler = async (event) => {
  const { id } = event.queryStringParameters;
  return {
    statusCode: 200,
    body: JSON.stringify({ id, message: "取得成功" }),
  };
};
```

- リクエストが来るたびに実行環境が起動し(コールドスタート)、処理が終わると環境は破棄される
- 実行時間・呼び出し回数に応じた従量課金が一般的で、リクエストがなければコストがほぼゼロになる

## つまずきやすい点

- 「コールドスタート」(しばらく呼ばれていない関数が初めて呼ばれる際に、実行環境の起動に追加の時間がかかる現象)は、レイテンシが重要なアプリケーションでは無視できない問題になることがある
- サーバーレス関数は基本的にステートレス(状態を保持しない)であることを前提に設計する必要がある。関数間でメモリ上の状態を共有したい場合は、外部のデータストア(データベース、キャッシュサービス)を介する必要がある
- 実行時間の上限(多くのプラットフォームで数分程度)があるため、長時間かかるバッチ処理のような用途には向かない。そのような処理は別のアーキテクチャ(常駐プロセス、キューイングによる分割処理等)を検討する必要がある

## 実装例(コード)

```typescript
// Next.jsのAPI RouteもVercel上でサーバーレス関数として実行される
export async function GET(request: Request) {
  return Response.json({ message: "Hello" });
}
```
