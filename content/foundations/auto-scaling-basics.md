## 概要

オートスケーリングは、CPU使用率やリクエスト数といった指標を監視し、あらかじめ設定した条件に応じてサーバーの台数(水平スケーリング)やスペック(垂直スケーリング)を自動的に増減させる仕組み。急激なアクセス増加に人手を介さず対応できる一方、設計を誤るとコストや可用性の問題を招く。

## 基礎文法

代表的なスケーリングの方向性:

- **水平スケーリング(スケールアウト/イン)**: サーバーの台数を増減させる。[ロードバランシング](/foundations/load-balancing-basics)と組み合わせて使われることが多い
- **垂直スケーリング(スケールアップ/ダウン)**: 1台あたりのCPU・メモリのスペックを増減させる。台数は変えないため設計はシンプルだが、上限に達すると台数を増やす以外の選択肢がなくなる

## つまずきやすい点

- スケーリングの判断指標(CPU使用率等)がスパイクしてから実際に新しいサーバーが起動するまでにはタイムラグがある。急激なアクセス集中(バズった、DDoS攻撃を受けた等)に対しては、スケーリングが間に合わずサービスがダウンすることもある
- サーバーを増やせばそのまま処理能力が増えるとは限らない。データベースのようなボトルネックが別に存在する場合、Webサーバーだけをスケールしても全体のスループットは上がらない
- スケールアウトしたサーバーがすぐにスケールインで削除されることを想定した設計(ステートレスな設計、[サーバーレスの基礎](/foundations/serverless-basics)と同様の考え方)にしていないと、削除されたサーバーが持っていたデータやセッションが失われる問題が起きる

## 実装例(コード)

```yaml
# Kubernetesでの水平オートスケーリング設定の例
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
spec:
  minReplicas: 2
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target: { type: Utilization, averageUtilization: 70 }
```
