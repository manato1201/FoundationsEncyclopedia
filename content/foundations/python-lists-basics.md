## 概要

C#やC++にある「サイズ固定の配列」型は、Pythonの標準的な書き方には登場しない。代わりに`list`という可変長のコレクション型が、[配列の基礎(C#)](/foundations/csharp-arrays-basics)が担う役割の多くを引き受けている。要素の型を混在させることもできる、動的型付け言語らしい柔軟性を持つ。

## 基礎文法

```python
scores = [90, 80, 70]     # リストの作成
scores.append(60)          # 末尾に要素を追加(可変長)
scores[0] = 100             # インデックスでの書き換え(0始まり)
scores.insert(1, 95)        # 途中への挿入
scores.remove(60)           # 値を指定して削除

length = len(scores)        # 要素数の取得
sliced = scores[1:3]        # スライス: インデックス1から3の手前まで
```

## つまずきやすい点

- Pythonの`list`は[配列と連結リストの違い](/foundations/array-vs-linked-list)でいう「配列」に近い実装(内部的には可変長配列)だが、任意の型を混在させられる点でC#の`List<T>`(単一の型`T`に固定)とは異なる。柔軟な反面、意図しない型が紛れ込んでも実行時までエラーに気づけないことがある
- スライス(`scores[1:3]`)は元のリストのコピーを新しく作る。元のリストへの参照(ビュー)ではないため、スライスした結果を変更しても元のリストには影響しない、という点はC++の`std::span`のような「参照ビュー」とは異なる挙動
- 本当に数値だけを大量に扱う場合、`list`よりも`array`モジュールや`numpy`配列の方が、メモリ効率・計算速度の面で有利なことが多い。`list`はあらゆる型を格納できる柔軟性の代償として、単純な数値配列としては効率が良くない

## 実装例(コード)

```python
# リスト内包表記との組み合わせ(既存のリストから新しいリストを作る)
scores = [90, 80, 70, 60]
passing = [s for s in scores if s >= 70]  # [90, 80, 70]
```
