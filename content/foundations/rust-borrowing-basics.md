## 概要

借用(borrowing)は、値の所有権を渡さずに一時的に参照(`&`)する仕組み。所有権をムーブし続けると不便なため、Rustでは「読み取り専用の参照(`&T`)を複数」または「書き込み可能な参照(`&mut T`)を1つだけ」のいずれかしか同時に存在できない、というルールでデータ競合をコンパイル時に防ぐ。

## 基礎文法

```rust
fn calculate_length(s: &String) -> usize { // 参照を受け取る(借用)。所有権は移動しない
    s.len()
}

fn main() {
    let s = String::from("hello");
    let len = calculate_length(&s); // &sで借用を渡す
    println!("{}の長さは{}", s, len); // sはまだ使える
}
```

- ライフタイム注釈(`'a`のような表記)は、「この参照は少なくともこの期間は有効である」という関係をコンパイラに伝えるためのもの。多くの場合はコンパイラが自動推論するため明示不要だが、複数の参照の関係が曖昧な場合に明示が必要になる

## つまずきやすい点

- 同じスコープ内で不変参照(`&T`)と可変参照(`&mut T`)を同時に持つことはできない。「読み取り中に書き換えられる」という状況をコンパイル時に排除するためのルールだが、初学者は「もう使っていないはずの参照」がエラーになる理由が分かりにくいことが多い
- 借用した値の元(所有者)がスコープを抜けて破棄されると、その参照は「ダングリング参照」になりうる。Rustのコンパイラはライフタイムを追跡してこれを検出し、コンパイルエラーとして防ぐ
- 関数から参照を返す場合、その参照が指す値がどこから来たものかをライフタイム注釈で明示する必要が生じることがある。「借用チェッカーを黙らせる」ためだけに闇雲に`'static`を付けると、意図しない長寿命化(メモリを解放しない設計)になることがある

## 実装例(コード)

```rust
// ライフタイム注釈が必要になる例: 戻り値の参照が引数のどちらに由来するか明示する
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```
