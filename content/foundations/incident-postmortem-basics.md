## 概要

システムに障害が起きたときは、**復旧を最優先**に、状況を共有しながら対応する。収まったあとに、**ポストモーテム**(振り返り)を書く。個人を責めるのではなく、**仕組みのどこを直せば再発しないか**を考える。

## 基礎文法

| 段階 | 内容 |
| --- | --- |
| 検知・連絡 | 気づいて、関係者へ知らせる |
| 復旧 | 影響を止める(原因は後でよい) |
| ポストモーテム | 経緯・原因・再発防止を記録する |

## つまずきやすい点

- 原因が分からなくても、まず切り戻しなどで復旧できないかを考える
- 個人の責任を追及すると、問題が隠されやすくなる。仕組みの改善に焦点を当てる
- ポストモーテムで決めた対策が、実行されないと意味がない。担当と期限を決める

## 実装例(コード)

```text
# ポストモーテムの項目の例
概要 / 影響 / 時系列 / 原因 / うまくいったこと / 改善点(担当・期限)
```
