## 概要

アプリは、ファイル・ネットワーク・メモリといった資源を、直接は操作できない。これらはOSが管理しており、アプリは**システムコール**という決められた窓口を通して、OSへ処理を依頼する。ふだんは、プログラミング言語のライブラリ関数(`open` や `print` など)が、内部でシステムコールを呼んでいる。

## 基礎文法

| 用語 | 意味 |
| --- | --- |
| ユーザーモード | アプリが動く、権限が制限された状態 |
| カーネルモード | OSの核が動く、特権のある状態 |
| システムコール | ユーザーモードからカーネルモードへ処理を依頼する窓口 |

## つまずきやすい点

- システムコールは、通常の関数呼び出しよりも切り替えの手間がかかる。細かい読み書きを大量に行うと、遅くなりやすい(まとめて読み書きする工夫がある)
- システムコールの種類や名前はOSごとに異なる(LinuxとWindowsで違う)。言語のライブラリが、その違いを隠していることが多い
- アプリが勝手にハードウェアを操作できないのは、この仕組みで守られているから

## 実装例(コード)

```bash
# Linuxで、プログラムが呼び出すシステムコールを観察する
strace -e trace=openat,read ls
```
