## 概要

C++で2次元的なデータを表現する方法は複数あり、性質が大きく異なる。生配列同士を組み合わせた`int grid[3][4]`は1つの連続したメモリブロックとして確保されるのに対し、`std::vector<std::vector<int>>`は「行ごとに独立したメモリ領域」を持つ、より柔軟だが断片化しやすい構造になる。

## 基礎文法

```cpp
// 固定サイズの二次元配列: 連続したメモリブロックとして確保される
int grid[3][4];
grid[0][0] = 1;
grid[2][3] = 99;

// std::vector<std::vector<int>>: 行ごとに独立した配列を持つ、可変長な二次元配列
std::vector<std::vector<int>> dynamicGrid(3, std::vector<int>(4, 0));
dynamicGrid[0][0] = 1;
```

## つまずきやすい点

- `int grid[3][4]`は[配列の基礎](/foundations/cpp-arrays-basics)で触れた「配列の減衰」の影響で、関数に渡す際に列数(4)を型情報として明示する必要がある(`void func(int grid[][4])`のような書き方)。行数・列数の両方を実行時に自由に変えたい場合は、`std::vector`ベースの構造の方が扱いやすい
- `std::vector<std::vector<int>>`は各行が独立したメモリ確保になるため、`int grid[3][4]`のような連続配列に比べて[キャッシュ効率](/foundations/cpu-memory-basics)が悪化しやすい。大規模なグリッドを高速に処理したい場合、1次元配列に「行×列数+列」のインデックス計算でアクセスする手法(疑似2次元配列)が使われることもある
- 二次元配列の初期化は行ごとに書く必要があり、初期化漏れの行があると不定な値が残ることがある。`std::vector`のコンストラクタ引数で初期値を指定する方が、初期化漏れを防ぎやすい

## 実装例(コード)

```cpp
// 1次元配列で疑似的な2次元配列を表現する例(キャッシュ効率重視)
std::vector<int> flatGrid(3 * 4, 0);
int row = 1, col = 2;
flatGrid[row * 4 + col] = 99; // grid[1][2] に相当
```
