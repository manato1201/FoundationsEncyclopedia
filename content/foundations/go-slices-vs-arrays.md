## 概要

Go言語には「配列(array)」と「スライス(slice)」という似て非なる2つのデータ構造がある。配列は長さが型の一部であり固定長、スライスは配列の一部(または全体)を指す可変長の「ビュー」。実務コードのほとんどはスライスを使う。

## 基礎文法

```go
var arr [3]int = [3]int{1, 2, 3} // 配列: 長さ3が型の一部([3]int)

slice := []int{1, 2, 3}          // スライス: リテラルで直接作成
slice = append(slice, 4)         // 要素を追加(必要なら内部でarrayが再確保される)

sub := slice[1:3]                // 元のスライスの一部を指す新しいスライス(内部配列は共有)
```

## つまずきやすい点

- スライスは内部的に「配列へのポインタ・長さ・容量」の3つを持つ構造体。スライスから作った別のスライス(`slice[1:3]`のような部分スライス)は元の配列を共有しているため、片方を変更するともう片方にも影響することがある
- `append`は容量が足りている場合は元の配列をそのまま使うが、容量を超えると新しい配列を確保してコピーする。この挙動の違いにより、「`append`した結果を別の変数で受けなかったため変更が反映されない」というバグが起きやすい(戻り値を必ず使う必要がある)
- 配列を関数に渡すと値渡しでコピーされる(サイズが大きいと高コスト)のに対し、スライスを渡すと内部のポインタがコピーされるだけで、実質的に参照渡しに近い挙動になる

## 実装例(コード)

```go
func modifySlice(s []int) {
    s[0] = 100 // 呼び出し元のスライスも変更される(同じ配列を指しているため)
}

func modifyArray(a [3]int) {
    a[0] = 100 // 呼び出し元には影響しない(コピーが渡されているため)
}
```
