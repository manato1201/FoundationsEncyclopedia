## 概要

再帰は、関数が自分自身を呼び出すことで、問題をより小さな(しかし同じ構造の)部分問題に分解して解く手法。木構造の走査、階乗の計算、[クイックソート](/foundations/big-o-basics)のような分割統治アルゴリズムなど、幅広い場面で使われる。

## 基礎文法

```python
def factorial(n: int) -> int:
    if n <= 1:  # 基底ケース: これ以上分解できない最小の問題
        return 1
    return n * factorial(n - 1)  # 再帰ケース: より小さな問題に分解する

factorial(5)  # 5 * 4 * 3 * 2 * 1 = 120
```

再帰関数には必ず2つの要素が必要:

- **基底ケース**: これ以上再帰しない、直接答えが分かる最小の問題
- **再帰ケース**: 問題をより小さな同じ形の問題に分解し、自分自身を呼び出す部分

## つまずきやすい点

- 基底ケースを書き忘れる(または条件を誤る)と、無限に自分自身を呼び出し続け、最終的にコールスタックが溢れて「スタックオーバーフロー」を起こす
- 再帰は直感的に書ける反面、呼び出しのたびに新しいスタックフレームが積まれるため、深い再帰(数万階層等)はメモリと速度の両面でコストがかかる。多くの言語はループ(反復)の方が同じ処理を高速に実行できることが多い
- 「末尾再帰」(自分自身の呼び出しが関数の最後の処理である形)は、一部の言語・処理系ではループと同等の効率に最適化される(末尾呼び出し最適化)が、C#やJavaScript、Pythonの標準的な処理系はこの最適化を行わないため、末尾再帰であっても深い再帰ではスタックオーバーフローのリスクが残る

## 実装例(コード)

```python
# 再帰を使ったフィボナッチ数列(素朴な実装、非効率な例としても有名)
def fibonacci(n: int) -> int:
    if n <= 1:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)  # 同じ計算を何度も繰り返してしまう
```
