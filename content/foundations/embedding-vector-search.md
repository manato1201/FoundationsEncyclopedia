## 概要

**埋め込み**は、文章を数値の並び(ベクトル)に変える処理。意味が近い文章は、ベクトルも近くなるように作られている。**ベクトル検索**は、質問をベクトルにして、近いベクトルを持つ文章を探す仕組みで、RAG(検索で取り出した文章をAIに渡して答えさせる方法)の土台になる。

## 基礎文法

ベクトル1件の容量は「次元数 × 1要素のバイト数」。float32は1要素4バイトなので、次のようになる。

| 次元数 | 1件の容量 | 比 |
| --- | --- | --- |
| 768 | 3072バイト | 1 |
| 128 | 512バイト | 約1/6 |

100万件持つなら、768次元で約3GB、128次元で約0.5GB(いずれも索引などの付加分を除く単純計算)。

## つまずきやすい点

- 次元を切り詰めると**精度は少し落ちる**。落ち幅はモデルとデータによって違うため、一般論ではなく自分のデータで確かめる
- どの次元を残してもよいわけではない。切り詰めに対応して作られたモデルかどうかを、モデルの公式の説明で確認する
- 容量だけでなく、検索速度にも次元数は効く。ただし速度は実装や索引の方式によっても大きく変わる

## 実装例(コード)

```python
# 容量の計算(float32は1要素4バイト)
def vector_bytes(dim: int, bytes_per_value: int = 4) -> int:
    return dim * bytes_per_value

print(vector_bytes(768))  # 3072
print(vector_bytes(128))  # 512
```

## 出典について

容量の計算は上記の単純な掛け算で確認できる。精度への影響は、実際のモデルとデータで検証が必要。
