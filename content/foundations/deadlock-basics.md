## 概要

デッドロックは、複数のプロセス(またはスレッド)が、互いに相手が保持しているリソースの解放を待ち続け、結果としてどちらも先に進めなくなる状態。マルチスレッドプログラミングで[ロック機構](/foundations/process-vs-thread)を使う際に典型的に発生しうる問題。

## 基礎文法

デッドロックが発生する典型例:

```
スレッドA: ロック1を取得 → ロック2の取得を試みる(待機)
スレッドB: ロック2を取得 → ロック1の取得を試みる(待機)
```

スレッドAはロック2が空くのを待ち、スレッドBはロック1が空くのを待つ。どちらも相手が持っているロックを解放しないため、永久に待ち続ける。

デッドロック成立の4条件(ホールド・アンド・ウェイト等):

- **相互排除**: リソースは同時に1つのプロセスしか使えない
- **占有と待機**: リソースを保持したまま、別のリソースを待つ
- **横取り不可**: 他のプロセスが保持するリソースを強制的に奪えない
- **循環待機**: 複数のプロセスが環状に互いのリソースを待っている

## つまずきやすい点

- デッドロックは発生条件が揃ったときにしか起きないため、テストでは再現しにくく、本番環境で低頻度にしか発生しないことがある。タイミング依存のバグとして非常に発見・再現が難しい部類に入る
- 対策の基本は「複数のロックを取得する順序を、プログラム全体で常に統一する」こと。上記の例でも、AとBが常に「ロック1→ロック2」の順で取得するようにすれば循環待機が起きなくなる
- デッドロックと「ライブロック」(処理は進んでいるように見えるが、実質的には堂々巡りをして先に進まない状態)は異なる問題であり、それぞれ別の対策が必要になる

## 実装例(コード)

```csharp
// ロック取得順序を統一してデッドロックを避ける例
lock (lockA)
{
    lock (lockB) // 常にA→Bの順で取得する規約を守る
    {
        // ...
    }
}
```
