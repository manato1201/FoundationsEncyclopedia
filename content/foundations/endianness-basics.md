## 概要

エンディアン(バイト順序)は、複数バイトで構成される数値(例: 4バイトの整数)を、メモリ上でどの順序で並べるかという規約。ビッグエンディアンは上位バイトから、リトルエンディアンは下位バイトから並べる。多くの現代的なCPU(x86、多くのARM設定)はリトルエンディアンを採用している。

## 基礎文法

数値`0x12345678`をメモリに格納する場合:

```
リトルエンディアン: [0x78, 0x56, 0x34, 0x12] (下位バイトが先頭)
ビッグエンディアン:   [0x12, 0x34, 0x56, 0x78] (上位バイトが先頭)
```

ネットワークプロトコル(TCP/IPのヘッダ等)は伝統的にビッグエンディアン(ネットワークバイトオーダー)を採用している。

## つまずきやすい点

- 異なるエンディアンのシステム間でバイナリデータをそのままやり取りすると、数値が正しく解釈されず、全く異なる値として読み込まれてしまう。ネットワーク通信やファイルフォーマットの設計では、送受信時にバイト順序を明示的に変換する必要がある
- セーブデータやネットワークパケットのようなバイナリフォーマットを自作する際、エンディアンを意識せずにメモリの内容をそのままファイルへダンプすると、異なるアーキテクチャの環境間でファイルの互換性が失われることがある
- テキストデータ(文字列)自体には直接的なエンディアンの概念はないが、UTF-16のような複数バイトで1文字を表現する文字エンコーディングでは、エンディアンの違いが文字化けの原因になることがある(BOMで区別することが多い)

## 実装例(コード)

```csharp
// C#でバイト順序を明示的に扱う例
byte[] bytes = BitConverter.GetBytes(0x12345678);
if (!BitConverter.IsLittleEndian)
{
    Array.Reverse(bytes); // 環境のエンディアンに応じて調整する
}
```
