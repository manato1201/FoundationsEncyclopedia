## 概要

C#は通常、[ガベージコレクション](/foundations/java-garbage-collection-basics)によって管理される参照でメモリを扱い、生のポインタを表に出さない設計になっている。しかし`unsafe`キーワードで囲んだブロックの中では、C++に近い、メモリアドレスを直接扱うポインタ操作が許可される。パフォーマンスが極めて重要な処理や、ネイティブライブラリとの相互運用で使われる。

## つまずきやすい点

- `unsafe`ブロックを使うには、プロジェクト設定で「Allow unsafe code」を明示的に有効にする必要がある。デフォルトでは無効になっており、これは「通常はポインタを使わせない」というC#の設計意図の表れ
- ポインタが指すメモリが、ガベージコレクションによって移動・解放されてしまうと、そのポインタは無効な領域を指す「ダングリングポインタ」になる。`fixed`キーワードでガベージコレクタによる移動を一時的に禁止する必要がある
- [C++のスマートポインタ](/foundations/cpp-smart-pointers)や[Goのポインタ](/foundations/go-pointers-basics)と異なり、C#のポインタはあくまで「例外的な機能」であり、通常のアプリケーションコードでは使用が推奨されない。パフォーマンスが本当にクリティカルな箇所に限定して使うべき機能

## 実装例(コード)

```csharp
unsafe
{
    int value = 42;
    int* p = &value;      // アドレスを取得
    *p = 99;               // ポインタ経由で値を書き換える
    Console.WriteLine(value); // 99 (元の変数にも反映される)
}
```
