## 概要

シャーディング(水平分割)は、巨大なテーブルのデータを、あるルール(シャードキー)に基づいて複数のデータベースサーバーに分散配置する手法。[レプリケーション](/foundations/database-replication-basics)が「同じデータの複製を複数台に持つ」のに対し、シャーディングは「異なるデータを複数台に分けて持つ」という違いがある。

## 基礎文法

```
ユーザーID % シャード数 でどのシャードに保存するか決める例:

ユーザーID 1, 4, 7, ... → シャード0
ユーザーID 2, 5, 8, ... → シャード1
ユーザーID 3, 6, 9, ... → シャード2
```

- シャードキーの選び方(ユーザーID、地域、日付等)によって、負荷の分散のされ方や、後述のクロスシャードクエリの発生頻度が大きく変わる

## つまずきやすい点

- 異なるシャードにまたがるデータを結合するクエリ(クロスシャードクエリ、例えば「ユーザーAとユーザーBの注文を比較する」)は、単一のデータベースでのJOINのようには実行できず、アプリケーション側で複数のシャードに個別にクエリを投げて結果を統合する必要が生じる
- シャードキーの選択を誤ると、特定のシャードにデータやアクセスが偏る「ホットスポット」が発生し、シャーディングによる負荷分散の効果が薄れることがある
- 一度決めたシャーディングの方式(シャード数、シャードキー)を後から変更するのは、既存データの大規模な再配置を伴う非常にコストの高い作業になる。将来のデータ量の見積もりを含めて、初期設計の時点で慎重な検討が必要になる

## 実装例(コード)

```python
# シャードキーからシャード番号を決定する簡単な例
def get_shard(user_id: int, shard_count: int) -> int:
    return user_id % shard_count
```
