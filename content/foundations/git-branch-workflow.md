## 概要

Gitでの開発では、`main`ブランチを直接変更するのではなく、機能ごとに新しいブランチを作成(`checkout -b`)してそこで変更・コミットを重ね、完成したら`main`へ統合(`merge`)するのが基本的なワークフロー。これにより、複数の変更を並行して進めても互いに干渉しにくくなる。

## 基礎文法

```bash
git checkout -b feature/add-login   # mainから分岐した新しいブランチを作成して移動
# ... ファイルを編集 ...
git add .
git commit -m "ログイン画面を追加"    # 変更をブランチに記録
git checkout main
git merge feature/add-login          # featureブランチの変更をmainに統合
```

## つまずきやすい点

- `merge`はfeatureブランチの変更履歴をそのまま残す(マージコミットが作られることが多い)のに対し、`rebase`は履歴を書き換えてmainの先端に積み直す。両者の違いを理解せずに使うと、共有ブランチの履歴を壊してしまうことがある
- マージ時に同じ箇所を両方のブランチで変更していると「コンフリクト」が発生し、手動で解決する必要がある
- ブランチを作らずに`main`で直接作業を進めてしまうと、複数の変更が同時に走った際に取り消し・切り分けが困難になる
