## 概要

エッジコンピューティングは、全ての処理を中央のデータセンターに集約するのではなく、ユーザーやデータの発生源に地理的に近い「エッジ」(CDNのエッジサーバー等)で計算処理の一部を行う考え方。[CDNの基礎](/foundations/cdn-basics)が静的コンテンツの配信を高速化する仕組みであるのに対し、エッジコンピューティングはそこにプログラムの実行まで持ち込む発展形といえる。

## 基礎文法

```typescript
// Vercel Edge Functionsの例: 中央のリージョンではなく、利用者に近いエッジで実行される
export const config = { runtime: "edge" };

export default function handler(request: Request) {
  const country = request.headers.get("x-vercel-ip-country");
  return new Response(`こんにちは、${country}からのアクセスですね`);
}
```

## つまずきやすい点

- エッジ環境は多くの場合、通常のサーバー実行環境(Node.js等)よりも制限された実行環境(軽量なJavaScriptランタイム等)であり、使えるAPIやライブラリに制約がある。「エッジで動くと思って実装したら、依存しているライブラリが対応していなかった」というつまずきが起きやすい
- エッジで処理を行う分、中央のデータベースへのアクセスは依然として地理的に遠い場合がある。エッジ側の処理を高速化しても、データベースへの往復がボトルネックのままでは全体の速度は改善しない
- 全ての処理をエッジに寄せればよいわけではない。強い一貫性が必要な処理(在庫の同時更新等)は、地理的に分散した環境よりも中央集権的な処理の方が整合性を保ちやすい場合がある

## 実装例(コード)

```typescript
// リクエスト元の地域によって表示を出し分ける、エッジならではの用途
const locale =
  request.headers.get("x-vercel-ip-country") === "JP" ? "ja" : "en";
```
