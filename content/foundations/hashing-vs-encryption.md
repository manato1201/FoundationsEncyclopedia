## 概要

ハッシュ化と暗号化は、どちらも「データを別の形に変換する」処理だが、目的と可逆性が根本的に異なる。ハッシュ化は元のデータへ戻せない一方向の変換で、暗号化は正しい鍵があれば元のデータへ戻せる(復号できる)変換。

## 基礎文法

| 観点   | ハッシュ化                   | 暗号化                                                            |
| ------ | ---------------------------- | ----------------------------------------------------------------- |
| 可逆性 | 不可逆(元に戻せない)         | 可逆(鍵があれば復号できる)                                        |
| 目的   | 改ざん検知、パスワードの保管 | 通信内容の秘匿([HTTPSとTLSの基礎](/foundations/https-tls-basics)) |
| 代表例 | SHA-256、bcrypt              | AES、RSA                                                          |

## つまずきやすい点

- パスワードは暗号化ではなく、ハッシュ化して保管するのが正しい。暗号化すると、鍵さえあれば元のパスワードが復元できてしまうため、鍵の漏洩がそのままパスワード漏洩に直結してしまう。ハッシュ化なら、たとえデータベースが漏洩してもハッシュ値から元のパスワードを直接復元することは(理論上)できない
- 単純なハッシュ関数(SHA-256をそのまま使う等)は、同じパスワードなら常に同じハッシュ値になる。攻撃者が事前計算したハッシュ値の対応表(レインボーテーブル)と照合されると突破されるため、「ソルト」(ランダムな値を混ぜる)や、意図的に計算コストを高くしたbcrypt・Argon2のような専用のハッシュ関数を使うのが実務標準
- 「ハッシュ値の衝突(異なる入力が同じハッシュ値になること)は理論上ゼロではない」という性質を悪用した攻撃も存在する。改ざん検知の用途では、衝突が発見されていない安全なハッシュアルゴリズムを選ぶ必要がある(MD5やSHA-1は既に安全でないとされている)

## 実装例(コード)

```python
# パスワードのハッシュ化にはbcryptのような専用ライブラリを使う(自前でSHA-256等を使わない)
import bcrypt

hashed = bcrypt.hashpw(b"my_password", bcrypt.gensalt())
bcrypt.checkpw(b"my_password", hashed)  # True
```
