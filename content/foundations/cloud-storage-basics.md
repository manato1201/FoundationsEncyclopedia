## 概要

クラウドストレージ(AWS S3、Google Cloud Storageなど)は、大量のファイル(画像、動画、バックアップ等)を保存するために設計されたサービス。従来の[ファイルシステム](/foundations/file-system-basics)のような階層的なディレクトリ構造ではなく、「バケット」という入れ物の中に「オブジェクト」をフラットに(あるいはキー名で疑似的なディレクトリのように)保存する、オブジェクトストレージという方式が主流。

## 基礎文法

```
バケット: my-app-assets
オブジェクトキー: images/2026/08/photo.png
```

- オブジェクトキーに`/`を含めることで、あたかもディレクトリ構造があるかのように見せられるが、実際には「単なる文字列のキー」であり、真の階層構造ではない
- 各オブジェクトはURLで直接アクセスできることが多く、静的なWebサイトやアセット配信の土台としても使われる

## つまずきやすい点

- サーバーレス関数(コンテナ)は実行のたびに新しい環境が起動するため、ローカルのファイルシステムに保存したデータは次の実行では消えている。永続化したいデータは必ずクラウドストレージやデータベースのような外部サービスに保存する必要がある
- バケットの公開範囲の設定を誤ると、機密情報を含むファイルが誰でもアクセスできる状態でインターネットに公開されてしまう事故が起こりうる。デフォルトでは非公開にし、必要な範囲だけを明示的に公開するのが安全な運用
- 大量の小さいファイルを扱う場合、1オブジェクトごとにAPIリクエストのオーバーヘッドがかかるため、単純なファイルシステムのように扱うと予想以上に遅くなることがある。用途に応じてCDNとの組み合わせ([CDNの基礎](/foundations/cdn-basics))を検討する

## 実装例(コード)

```bash
# AWS CLIでのアップロード例
aws s3 cp ./local-file.png s3://my-app-assets/images/2026/08/photo.png
```
