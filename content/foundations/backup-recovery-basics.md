## 概要

データの消失に備えて、**バックアップ**を取る。どれだけ前の時点まで戻せるか(**RPO**)、どれだけの時間で復旧するか(**RTO**)を、先に決めておくと、方法や頻度を選びやすい。

## 基礎文法

| 用語 | 意味 |
| --- | --- |
| RPO | 戻せる時点の目標(例: 1時間前まで) |
| RTO | 復旧にかかる時間の目標(例: 4時間以内) |
| フル / 増分 | 全体を取る / 前回からの変更だけを取る |

## つまずきやすい点

- **復元を試していないバックアップは、使えるとは限らない**。定期的に、実際に戻す練習をする
- バックアップを、元のデータと同じ場所や同じ権限に置くと、一緒に失われたり、一緒に壊されたりする
- 取得の間隔が長いほど、失われるデータが増える。RPOに合わせて決める

## 実装例(コード)

```bash
# PostgreSQLの例: データベースをファイルに書き出す
pg_dump mydb > backup.sql
# 復元の例
psql mydb_restore < backup.sql
```
