## 概要

**リファクタリング**は、プログラムの外から見た動き(仕様)を変えずに、内部の作りを改善すること。名前を分かりやすくする、長い関数を分ける、重複をまとめる、といった作業が含まれる。あとで変更しやすく、バグを見つけやすくするために行う。

## 基礎文法

| 代表的な整理 | 内容 |
| --- | --- |
| 名前の変更 | 変数・関数の名前を、役割が分かる名前にする |
| 関数の切り出し | 長い処理を、意味のある単位の関数に分ける |
| 重複の解消 | 同じ処理を1か所にまとめる |

## つまずきやすい点

- テストがないまま行うと、動きが変わったことに気づけない。先にテストを用意するか、手元で動作を確かめられる状態にする
- 一度に大きく直すと、どこで壊れたか分からなくなる。小さく直して、そのたびに確かめる
- 動作を変える修正(バグ修正・機能追加)と混ぜると、変更の確認が難しくなる。別の変更として行う

## 実装例(コード)

```python
# 前: 計算の意味が分かりにくい
def f(a, b):
    return a * b * 1.1

# 後: 動きは同じで、名前と意味を明らかにした
TAX_RATE = 1.1

def price_with_tax(unit_price, quantity):
    return unit_price * quantity * TAX_RATE
```
