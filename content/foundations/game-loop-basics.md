## 概要

ゲームループは、「入力を受け付ける」「ゲームの状態を更新する」「画面を描画する」という3つの処理を、1秒間に何十回も繰り返すことでゲームが「動いている」ように見せる仕組み。Unity/Unreal/自作エンジンを問わず、あらゆるリアルタイムアプリケーションの根幹にある構造。

## 基礎文法

```
while (ゲームが実行中) {
    input();   // プレイヤーの入力を取得する
    update();  // ゲームの状態(位置、当たり判定等)を更新する
    render();  // 現在の状態を画面に描画する
}
```

- Unity/Unrealのようなエンジンでは、このループ自体はエンジン側が管理しており、開発者は`Update()`のような「毎フレーム呼ばれる関数」の中身を書くだけで済む

## つまずきやすい点

- 更新(update)の処理を、実際の経過時間([デルタタイムの基礎](/foundations/delta-time-basics))を考慮せずに固定量ずつ進めると、フレームレートが変動する環境(重い処理が挟まった瞬間等)でゲームの進行速度が不安定になる
- 描画(render)の処理が重いと、更新(update)の頻度自体も引きずられて低下することがある。負荷の高いゲームでは、更新と描画を別々のペースで実行する設計(固定タイムステップの更新+可変レートの描画)が使われることもある
- ゲームループは単純な仕組みに見えるが、「入力を受け取ったタイミングと、実際にその入力が反映されるタイミングのズレ」([入力バッファリングの基礎](/foundations/input-buffering-basics))のような、体感の良さに直結する細かい調整が奥深い分野になっている

## 実装例(コード)

```csharp
// Unityにおける「ゲームループの中身」に相当するコード
void Update()
{
    HandleInput();
    UpdateGameState();
    // 描画自体はUnityのレンダリングパイプラインが自動的に行う
}
```
