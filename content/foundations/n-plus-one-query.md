## 概要

N+1問題は、一覧を取得する1回のクエリのあと、一覧の各行(N件)について、関連するデータを取得するクエリが1回ずつ発行されてしまう問題。件数が増えるほどクエリが増え、応答が遅くなる。ORMを使うと、気づかないうちに起きやすい。

## 基礎文法

| 状態 | クエリの回数 |
| --- | --- |
| N+1が起きている | 1回(一覧) + N回(各行の関連データ) |
| まとめて取得した | 1〜2回(JOINや、IN句での一括取得) |

## つまずきやすい点

- 件数が少ない開発中は気づきにくく、データが増えた本番で遅くなる
- 解決は「JOINで1回にする」か「関連データをIN句でまとめて取る」。どちらが良いかは、データの形とORMの機能による
- まとめて取得しすぎると、使わないデータまで読み込んで、別の無駄が生まれる。必要な列と関連だけを取る

## 実装例(コード)

```sql
-- N+1: 一覧のあとに、記事ごとに1回ずつ
SELECT * FROM posts;
SELECT * FROM users WHERE id = 1;
SELECT * FROM users WHERE id = 2;

-- まとめて取得(JOIN)
SELECT posts.*, users.name
FROM posts
JOIN users ON users.id = posts.user_id;
```
