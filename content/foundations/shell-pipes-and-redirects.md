## 概要

シェル(bash等)には、標準入力・標準出力・標準エラー出力という3つの基本的な入出力の流れがある。パイプ(`|`)は、あるコマンドの標準出力を別のコマンドの標準入力へ直接つなぎ、リダイレクト(`>`、`<`)は、標準入出力をファイルへつなぎ替える。

## 基礎文法

```bash
cat access.log | grep "ERROR" | wc -l   # ログからERRORを含む行を抽出し、その件数を数える

echo "Hello" > output.txt   # 標準出力をファイルへ書き込む(上書き)
echo "World" >> output.txt  # 標準出力をファイルへ追記する

sort < input.txt             # ファイルの内容を標準入力として渡す

command 2> error.log         # 標準エラー出力だけをファイルへリダイレクト
command > all.log 2>&1       # 標準出力・標準エラー出力の両方を同じファイルへ
```

## つまずきやすい点

- `>`は上書き、`>>`は追記という違いを混同すると、意図せず既存のログファイルの内容を消してしまうことがある
- `2>&1`の順序は重要。`command > all.log 2>&1`は正しく両方をリダイレクトするが、`command 2>&1 > all.log`は意図通りに動かない(この時点では標準エラー出力はまだ元の出力先を指しているため)。リダイレクトは左から右に順番に評価されるという理解が必要
- パイプで繋いだコマンドのうち、途中のコマンドが失敗しても、パイプ全体の終了ステータスはデフォルトでは最後のコマンドの結果だけを見る。途中の失敗も検知したい場合は`set -o pipefail`のような設定が必要になる

## 実装例(コード)

```bash
# パイプで複数のコマンドを組み合わせて集計する例
cat access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head -10
```
