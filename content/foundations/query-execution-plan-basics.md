## 概要

データベースは、SQLを受け取ると、どのインデックスを使い、どの順にテーブルを結合するかの**実行計画**を立てる。`EXPLAIN` を付けると、その計画を見られる。遅いクエリの原因を探す、最初の手がかりになる。

## 基礎文法

| 見るところ | 意味 |
| --- | --- |
| 全表スキャン | テーブルの全行を読んでいる(遅くなりやすい) |
| インデックスの使用 | インデックスで絞り込んでいる |
| 見積もりの行数 | 処理する行数の見込み |

## つまずきやすい点

- 表示の形式や項目は、データベースの種類によって異なる。使うものの説明を確認する
- インデックスがあっても、条件の書き方(列に関数をかけるなど)で、使われないことがある
- データの量や偏りで、計画は変わる。本番に近いデータで確認する

## 実装例(コード)

```sql
EXPLAIN SELECT * FROM orders WHERE user_id = 100;
-- 結果で、インデックスが使われているか、全表スキャンかを確認する
```
