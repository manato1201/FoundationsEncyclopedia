## 概要

HTTPメソッドは、[HTTPリクエスト](/foundations/http-request-response-basics)が「取得したいのか」「作成したいのか」「更新したいのか」といった意図を表す動詞。GET・POST・PUT・DELETEをはじめ複数の種類があり、それぞれ「安全性」(データを変更しないか)と「冪等性」(同じリクエストを何度送っても結果が同じか)という性質が定義されている。

## 基礎文法

| メソッド | 用途                       | 安全 | 冪等        |
| -------- | -------------------------- | ---- | ----------- |
| GET      | データの取得               | ✓    | ✓           |
| POST     | 新規作成、副作用のある操作 | ✗    | ✗           |
| PUT      | リソース全体の置き換え     | ✗    | ✓           |
| PATCH    | リソースの部分更新         | ✗    | ✗(実装依存) |
| DELETE   | リソースの削除             | ✗    | ✓           |

## つまずきやすい点

- 「安全」とは「データを変更しない」という意味であり、GETリクエストで意図的にデータを変更する処理(例: リンクを踏むだけで削除される機能)を実装すると、ブラウザのプリフェッチ機能やクローラーが意図せずデータを変更してしまう事故につながる
- 「冪等」とは「同じリクエストを何度送っても結果が変わらない」という意味。PUTは「このIDのリソースをこの内容に置き換える」という操作のため、何度送っても最終結果は同じで冪等だが、POSTは「新しいリソースを作成する」ため、2回送ると2つのリソースが作られてしまい冪等ではない
- ネットワークが不安定な環境では、リクエストが実際にはサーバーに届いていたのに、レスポンスが返ってこず失敗と誤認してリトライしてしまうことがある。冪等なメソッドであれば安全に再送できるが、POSTのような非冪等なメソッドを安易に自動リトライすると、二重登録のような問題を引き起こしうる

## 実装例(コード)

```typescript
// REST APIでのメソッドの使い分けの例
fetch(`/api/entries/${id}`, { method: "PUT", body: JSON.stringify(fullData) }); // 全体置き換え
fetch(`/api/entries/${id}`, {
  method: "PATCH",
  body: JSON.stringify({ name }),
}); // 部分更新
```
