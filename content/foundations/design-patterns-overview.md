## 概要

デザインパターンは、ソフトウェア設計で繰り返し現れる問題に対する、再利用可能な解決策のカタログ。有名な「GoF(Gang of Four)デザインパターン」は、23種類のパターンを「生成に関するパターン」「構造に関するパターン」「振る舞いに関するパターン」の3つに分類している。

## 基礎文法

3分類とその代表例:

- **生成に関するパターン**: オブジェクトの生成方法を抽象化する(Factory Method、Singleton、Builder等)
- **構造に関するパターン**: クラスやオブジェクトの組み合わせ方を扱う(Adapter、Decorator、Composite等)
- **振る舞いに関するパターン**: オブジェクト間の責務分担やアルゴリズムの構造を扱う(Observer、Strategy、State等)

```csharp
// Observerパターンの例: C#のeventキーワードは、まさにこのパターンの言語レベルでの実装
public class Health
{
    public event Action<int> OnDamaged; // 「観察者」が変化を購読する
}
```

## つまずきやすい点

- デザインパターンは「これを使えば良い設計になる」という魔法の道具ではない。適用すべきでない場面で無理に使うと、単純な問題を過度に複雑化させる「パターンのための パターン」になりがち
- 同じ問題に対して複数のパターンが候補になりうることが多く、「唯一の正解」があるわけではない。プロジェクトの規模・将来の変更可能性・チームの理解度を踏まえて選択する必要がある
- 現代のプログラミング言語には、GoFパターンが考案された当時にはなかった機能(ラムダ式、`event`キーワード、ジェネリクス等)が備わっており、それらの言語機能自体が特定のパターンを簡潔に表現できることがある。パターンの「名前」を覚えるより、その名前が解決しようとしている「問題の本質」を理解する方が実務的な価値が高い

## 実装例(コード)

```typescript
// Strategyパターンの例: アルゴリズムを実行時に切り替え可能にする
type SortStrategy = (items: number[]) => number[];

function sortWith(items: number[], strategy: SortStrategy): number[] {
  return strategy(items);
}
```
