## 概要

所有権(ownership)は、Rustがガベージコレクションなしにメモリ安全性を保証するための中核ルール。「各値は常にちょうど1つの所有者を持つ」「所有者がスコープを抜けると値は破棄される」「所有権は移動(move)できるが、コピーされない限り複数の変数が同時に同じ値を所有することはない」という3つのルールに基づく。

## 基礎文法

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1; // s1の所有権がs2へムーブされる。s1はもう使えない

    println!("{}", s2); // OK
    // println!("{}", s1); // コンパイルエラー: s1はムーブ済み
}
```

- `i32`のようなプリミティブ型は`Copy`トレイトを実装しているため、代入時にムーブではなくコピーされる(元の変数も引き続き使える)
- `String`のようなヒープを使う型は、デフォルトでは代入時にムーブが起きる

## つまずきやすい点

- 他の言語(C#/Javaの参照型代入、Pythonの変数束縛)に慣れていると、「代入したら両方使えるはず」という直感が裏切られる。ムーブ後の変数を使おうとするコンパイルエラーは、Rust初学者が最も頻繁に遭遇するエラーの1つ
- 関数に値を渡すと、参照でない限り所有権もその関数にムーブされる。呼び出し元で値を使い続けたい場合は、[借用(参照)](/foundations/rust-borrowing-basics)を使うか、値を明示的にクローンする必要がある
- 所有権システムは実行時コストなしにメモリ安全性を保証する代わりに、コンパイル時の学習コストが高い。「なぜこのコードがコンパイルを通らないのか」を所有権のルールに沿って読み解く訓練が必要になる

## 実装例(コード)

```rust
fn takes_ownership(s: String) {
    println!("{}", s);
} // sはここでスコープを抜けドロップされる(メモリが解放される)

fn main() {
    let s = String::from("hello");
    takes_ownership(s); // sの所有権が関数にムーブされる
    // ここでsはもう使えない
}
```
