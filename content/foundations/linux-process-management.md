## 概要

Linux上で動いている全てのプログラムは「プロセス」として管理されており、それぞれ固有のプロセスID(PID)を持つ。`ps`コマンドで現在実行中のプロセスの一覧を確認し、問題があれば`kill`コマンドでシグナルを送って終了させる、というのが基本的なプロセス管理の流れ。

## 基礎文法

```bash
ps aux             # 実行中の全プロセスを詳細表示
ps aux | grep node  # "node"を含むプロセスだけに絞り込む

kill 1234           # PID 1234のプロセスへSIGTERM(穏やかな終了要求)を送る
kill -9 1234         # PID 1234のプロセスへSIGKILL(強制終了)を送る
```

## つまずきやすい点

- `kill`という名前から「強制終了させるコマンド」と誤解されがちだが、実際にはプロセスへ「シグナル」を送るコマンドであり、デフォルトのSIGTERMは「終了してください」という穏やかな要求。プロセス側はこのシグナルを受け取って、後片付け(ファイルのクローズ等)をしてから終了できる
- `kill -9`(SIGKILL)は、プロセスに後片付けの機会を与えずに即座に強制終了させる。データベースのようなプロセスに対して安易に使うと、書き込み中のデータが破損する可能性がある。まずは通常の`kill`(SIGTERM)を試し、それでも終了しない場合の最終手段として使うのが基本
- 親プロセスを`kill`しても、子プロセスが自動的に終了するとは限らない。子プロセスだけが取り残されて動き続ける「ゾンビプロセス」や孤立プロセスが発生することがあり、プロセスグループを意識した終了処理が必要な場合がある

## 実装例(コード)

```bash
# 特定のポートを使っているプロセスを見つけて終了させる例
lsof -i :3000        # ポート3000を使っているプロセスを確認
kill $(lsof -t -i :3000)  # そのプロセスを終了させる
```
