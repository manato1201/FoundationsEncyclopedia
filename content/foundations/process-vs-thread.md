## 概要

プロセスは、OSがメモリ空間・リソースを割り当てて実行するプログラムの単位。スレッドは、そのプロセスの中でCPU実行の単位となる、より細かい粒度の存在。1つのプロセスは複数のスレッドを持つことができ、それらは同じメモリ空間を共有する。

## 基礎文法

- **プロセス**: 独立したメモリ空間を持つ。プロセス間でデータをやり取りするにはIPC(プロセス間通信、パイプ・共有メモリ・ソケット等)が必要
- **スレッド**: 同じプロセス内のスレッド同士はメモリ空間を共有する。変数を直接共有できる反面、同時に書き換えるとデータ競合(レースコンディション)が起きうる

## つまずきやすい点

- 「プロセスを分ける=安全だが重い」「スレッドを分ける=軽いが危険」という単純化はおおむね正しいが、スレッド生成自体のコストや、共有メモリを守るためのロック機構(mutex等)の設計を誤ると、スレッドを使ってもかえって遅くなることがある
- マルチスレッドプログラミングでは、複数スレッドが同じ変数に同時アクセスするデータ競合を防ぐため、ロック・アトミック操作・イミュータブルなデータ構造など何らかの同期手段が必要になる
- ゲームエンジンのメインスレッド(Unityの多くのAPIはメインスレッド専用)のように、「特定のスレッドからしか呼べないAPI」が存在する場合、バックグラウンドスレッドから直接呼び出すと例外やクラッシュにつながる

## 実装例(コード)

```csharp
// スレッドプールを使った並行処理の例(C#)
await Task.Run(() =>
{
    // 重い計算処理をバックグラウンドスレッドで実行
    var result = HeavyComputation();
});
// UnityのAPIをここで直接呼ぶ場合はメインスレッドに戻す必要がある
```
