## 概要

HTTPキャッシュは、一度取得した画像・CSS・データなどを手元に保存して、次回以降の取得を省く仕組み。通信が減って、表示が速くなり、サーバーの負荷も減る。使い回してよいかどうかは、サーバーが返す**ヘッダー**で決まる。

## 基礎文法

| ヘッダー | 意味 |
| --- | --- |
| `Cache-Control: max-age=3600` | 3600秒(1時間)は、問い合わせずに使い回してよい |
| `Cache-Control: no-store` | 保存しない |
| `ETag` | 内容の識別子。変わったかの確認に使う |
| `If-None-Match` | ブラウザが、保存したETagを添えて「変わったか」を尋ねる |

## つまずきやすい点

- 長いキャッシュ期間を設定すると、内容を更新しても、古いものが表示され続けることがある。ファイル名にハッシュを含める(例: `app.3f2a1c.js`)と、更新時に新しいファイルとして扱える
- ログイン後のデータなど、人ごとに異なる内容は、共有されるキャッシュ(CDNなど)に置かない設定にする
- `no-cache`は「保存しない」ではなく、「使う前に確認する」の意味。保存させたくないときは`no-store`

## 実装例(コード)

```http
HTTP/1.1 200 OK
Cache-Control: max-age=3600
ETag: "abc123"
```
