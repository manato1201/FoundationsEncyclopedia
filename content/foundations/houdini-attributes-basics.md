## 概要

アトリビュートは、Houdiniのジオメトリを構成する各要素(ポイント、頂点、プリミティブ、ジオメトリ全体)に付与されたデータ。位置を表す`P`、法線を表す`N`、色を表す`Cd`のような組み込みアトリビュートに加え、任意の名前でカスタムアトリビュートを追加できる。[VEXの基礎](/foundations/houdini-vex-basics)で扱った`@P`のような記法は、このアトリビュートへアクセスするための構文。

## 基礎文法

アトリビュートが定義されるクラス(単位):

- **Point(ポイント)**: 頂点の位置に対応する、最も基本的な単位
- **Vertex(頂点)**: ポイントがどのプリミティブに属するかという文脈込みの単位(同じポイントでも複数のプリミティブに属す場合、頂点ごとに異なる値を持てる)
- **Primitive(プリミティブ)**: 面やカーブなど、複数のポイントで構成される要素単位
- **Detail(ジオメトリ全体)**: そのジオメトリ1つにつき1つだけ存在する、全体設定のような値

```
@P (ポイントの位置)
@N (法線)
@Cd (頂点カラー)
i@id (整数型のカスタムアトリビュート)
```

## つまずきやすい点

- 同じ「色」を表現するにしても、Point・Vertex・Primitiveのどのクラスに定義するかで意味が変わる。頂点ごとに異なる色(1つの面の中でグラデーションさせたい等)を表現したい場合はVertexクラスが必要になるが、Pointクラスでは表現できない
- アトリビュートの型(整数、浮動小数点数、ベクトル、文字列)を誤って混在させると、後続のノードで意図しないエラーや変換が発生することがある。VEXコード内でアトリビュートの型を明示するプレフィックス(`i@`、`f@`、`v@`等)を意識する必要がある
- 不要になったアトリビュートを削除せずに残しておくと、ジオメトリのデータ量が増え、ネットワーク全体のパフォーマンスに影響することがある。デバッグ用に追加したアトリビュートは、最終的なネットワークからは削除するのが望ましい

## 実装例(コード)

```
// VEXでカスタムアトリビュートを追加・参照する例
f@custom_value = sin(@P.x) * 0.5;
```
