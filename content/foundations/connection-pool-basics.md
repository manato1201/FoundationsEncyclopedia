## 概要

データベースへの接続は、作るのに時間がかかり、データベース側の負荷にもなる。**コネクションプール**は、接続をあらかじめ作ってためておき、処理が必要なときに借りて、終わったら返す仕組み。接続の作り直しを避け、同時に使う接続の数も制御できる。

## 基礎文法

| 設定 | 意味 |
| --- | --- |
| 最大接続数 | プールが持つ接続の上限 |
| 待機のタイムアウト | 空きを待つ最大の時間 |
| アイドルの寿命 | 使われない接続を閉じるまでの時間 |

## つまずきやすい点

- 最大接続数は、大きければ良いわけではない。データベース側の上限や、複数のアプリが同時に使う数を合わせて決める
- 借りた接続を**返し忘れる**と、プールが空になって、ほかの処理が待たされる。使い終わったら必ず返す(例外のときも)
- サーバーレス環境では、実行のたびに接続が作られやすい。接続の数が増えすぎないよう、プール用の仕組みを使う場合がある

## 実装例(コード)

```python
from sqlalchemy import create_engine, text

engine = create_engine("postgresql://user:pass@localhost/db", pool_size=5, max_overflow=2)

with engine.connect() as conn:          # プールから接続を借りる
    conn.execute(text("SELECT 1"))      # 抜けるとプールへ返される
```
