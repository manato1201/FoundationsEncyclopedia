## 概要

SQLインジェクションは、ユーザーが入力した値をそのままSQL文の一部として文字列連結してしまうことで、攻撃者が意図しないSQLコマンドを紛れ込ませられる脆弱性。データの窃取・改ざん・削除に直結しうる、Webアプリケーションにおける最も古典的かつ危険な脆弱性の1つ。

## 基礎文法

脆弱なコードの例:

```php
// ユーザー入力を直接文字列連結している(危険)
$id = $_GET['id'];
$query = "SELECT * FROM users WHERE id = " . $id;
// $id に "1 OR 1=1" が渡されると、全ユーザーの情報が取得されてしまう
```

安全な書き方([PDOによるDB接続の基礎](/foundations/php-pdo-basics)参照):

```php
$stmt = $pdo->prepare("SELECT * FROM users WHERE id = :id");
$stmt->execute(["id" => $id]); // 値としてバインドされ、SQLとして解釈されない
```

## つまずきやすい点

- 「入力値のバリデーション(数字だけを許可する等)をしているから安全」という思い込みは危険な場合がある。バリデーションをすり抜けるパターンは常に存在しうるため、根本的な対策はプリペアドステートメント(バインド機構)を使うことにある
- ORM(データベース操作を抽象化するライブラリ)を使っていても、生のSQL文字列を組み立てる機能(raw query的なAPI)を安易に使うと、同じ脆弱性を作り込んでしまうことがある
- 管理画面や社内向けツールのように「外部に公開していないから安全」という考えも危険。内部ネットワークへの侵入を許した攻撃者にとって、内部向けツールの脆弱性は次の攻撃の足がかりになりうる
