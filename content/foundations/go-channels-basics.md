## 概要

チャネル(channel)は、Goroutine同士がデータを送受信するための型付きの通信路。Go言語の並行処理の哲学は "Don't communicate by sharing memory; share memory by communicating"(メモリを共有して通信するな、通信することでメモリを共有せよ)という言葉に集約され、チャネルはその中核をなす。

## 基礎文法

```go
ch := make(chan int)       // バッファなしチャネル
bufferedCh := make(chan int, 10) // バッファ付き(容量10)チャネル

go func() {
    ch <- 42 // チャネルへ送信(受信側がいなければブロックする)
}()

value := <-ch // チャネルから受信(送信されるまでブロックする)
```

- バッファなしチャネル: 送信と受信が同時に揃わないとブロックする(同期的な受け渡し)
- バッファ付きチャネル: バッファが埋まるまでは送信側がブロックしない(非同期的な受け渡し)

## つまずきやすい点

- 受信者がいないチャネルに送信し続けたり、送信者がいないチャネルから受信しようとしたりすると、Goroutineが永久にブロックされる(デッドロック)。特にバッファなしチャネルはこの罠にはまりやすい
- チャネルを`close()`した後にさらに送信しようとするとpanicになる。一方、`close()`されたチャネルからの受信はゼロ値を即座に返すため、`close`の意味(「もうデータは来ない」という合図)を正しく理解しておく必要がある
- `select`文で複数のチャネルを待つ際、どのケースも準備できていない場合は全体がブロックする。タイムアウトを設けたい場合は`time.After`をケースの1つとして組み込むのが定石

## 実装例(コード)

```go
select {
case msg := <-ch:
    fmt.Println("受信:", msg)
case <-time.After(3 * time.Second):
    fmt.Println("タイムアウト")
}
```
