## 概要

**APIゲートウェイ**は、多数のAPIやサービスの前に置く、共通の入口。認証・レート制限・ルーティング・ログの記録など、各サービスに共通する処理をまとめて受け持つ。クライアントは、裏側のサービスの数や場所を知らなくてよい。

## 基礎文法

| 役割 | 内容 |
| --- | --- |
| ルーティング | URLに応じて、サービスを選ぶ |
| 認証・認可 | 共通の本人確認と権限の確認 |
| レート制限 | リクエストの数を制御する |
| ログ・監視 | アクセスの記録を集める |

## つまずきやすい点

- ゲートウェイが止まると、すべてのAPIが使えなくなる。冗長な構成にする
- 処理を詰め込みすぎると、ゲートウェイが重くなり、変更もしにくくなる。共通の処理にとどめる
- リバースプロキシや、ロードバランサーと役割が重なる部分がある。目的に合うものを選ぶ

## 実装例(コード)

```yaml
# 擬似的な設定の例(製品によって書き方は異なる)

  - path: /orders/*

  - rate-limit: 60/min
```
