## 概要

公開したAPIを使う利用者は、こちらの都合で変更されると、動かなくなる。変更の影響を抑えるため、互換性を壊す変更は、新しい**版**として分けて提供する。

## 基礎文法

| 方式 | 例 |
| --- | --- |
| URLに含める | `/v1/users` → `/v2/users` |
| ヘッダーで指定する | `Accept: application/vnd.example.v2+json` |

## つまずきやすい点

- 互換性を壊す変更を、予告なしに同じ版へ入れない
- 版を増やしすぎると、保守する対象が増える。古い版を、計画的に終了する
- 項目の追加でも、利用者のコードが想定外の項目に対応できない場合がある。変更の内容を、事前に知らせる

## 実装例(コード)

```http
GET /v2/users/1 HTTP/1.1
Host: api.example.com
```
