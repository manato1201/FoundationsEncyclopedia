## 概要

Blenderには標準で2つの主要なレンダーエンジンが搭載されている。Eeveeはゲームエンジンに近いリアルタイムレンダリング技術をベースにしており高速だが近似計算が多く、Cyclesはパストレーシング(光線を物理的にシミュレーションする手法)による高品質だが計算コストの高いレンダリングを行う。

## 基礎文法

| 観点 | Eevee                                      | Cycles                                |
| ---- | ------------------------------------------ | ------------------------------------- |
| 速度 | 高速(リアルタイムに近い)                   | 低速(1枚のレンダリングに時間がかかる) |
| 品質 | 近似計算による見た目重視                   | 物理的に正確な光の挙動                |
| 用途 | プレビュー、リアルタイムアプリ向け素材確認 | 最終的な高品質レンダリング            |

## つまずきやすい点

- Eeveeで見た目を確認しながら作業し、最終的にCyclesでレンダリングすると、反射や影の表現が異なり、見た目の印象が変わることがある。特にガラスや金属のようなマテリアルはこの差が顕著に出やすい
- Cyclesはノイズ(ざらつき)が出やすいレンダリング方式のため、サンプル数(計算回数)を増やすことでノイズを減らせるが、その分レンダリング時間も比例して増加する。ノイズ除去(デノイズ)機能と組み合わせて実用的な時間内に収める工夫が必要になる
- ゲームエンジン(Unity/Unreal)向けにアセットを作る場合、最終的な見た目はゲームエンジン側のレンダラーで決まるため、Blender側でどちらのエンジンを使って確認していたかは、そのままゲーム内の見た目を保証するものではない

## 実装例(コード)

```python
import bpy

# レンダーエンジンをCyclesに切り替える例
bpy.context.scene.render.engine = 'CYCLES'
bpy.context.scene.cycles.samples = 128
```
