## 概要

ソートアルゴリズムは無数に存在するが、大きく「単純だが計算量が悪いもの([O(n²)](/foundations/big-o-basics))」と「やや複雑だが計算量が良いもの([O(n log n)](/foundations/big-o-basics))」に分けられる。加えて「安定ソートかどうか」(同じ値を持つ要素の元の相対順序が保たれるか)も、実務での選択基準になる。

## 基礎文法

代表的な分類:

| アルゴリズム   | 平均計算量            | 安定性 | 特徴                                 |
| -------------- | --------------------- | ------ | ------------------------------------ |
| バブルソート   | O(n²)                 | 安定   | 実装は単純だが実務ではほぼ使われない |
| 挿入ソート     | O(n²)                 | 安定   | データがほぼソート済みの場合は高速   |
| マージソート   | O(n log n)            | 安定   | 分割統治、追加メモリが必要           |
| クイックソート | O(n log n)(最悪O(n²)) | 不安定 | 実測は非常に速いが最悪ケースがある   |
| ヒープソート   | O(n log n)            | 不安定 | 追加メモリをほぼ必要としない         |

## つまずきやすい点

- 「O(n log n)は常にO(n²)より速い」というのは漸近的な(nが十分大きい場合の)話であり、要素数が少ない場合は定数倍の影響で単純なアルゴリズムの方が実測で速いことがある。多くの標準ライブラリのソート実装は、小さい範囲は挿入ソートに切り替えるハイブリッド方式を採っている
- 「安定ソート」であるかどうかは、複数のキーで段階的にソートしたい場合(まずカテゴリでソートし、その中で名前順にソートする等)に重要になる。不安定なソートを使うと、先にソートした順序が後のソートで壊れてしまうことがある
- 実務では自分でソートアルゴリズムを実装する機会は少なく、標準ライブラリのソート関数(多くは内部でクイックソート・マージソート・ヒープソートを組み合わせたIntrosort等を採用)を使うのが基本。とはいえ計算量・安定性の特性を理解していないと、標準ライブラリの挙動(特に安定性)を誤って前提にしてしまうことがある

## 実装例(コード)

```python
# Pythonのsorted()は安定ソート(Timsort)を保証している
items = [("b", 2), ("a", 1), ("a", 2)]
sorted(items, key=lambda x: x[0])  # "a"同士の相対順序(1, 2)は保たれる
```
