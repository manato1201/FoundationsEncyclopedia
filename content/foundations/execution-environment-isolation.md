## 概要

コードやAIエージェントが動く環境を、本体から切り離して安全に動かしたいとき、分離の方法はいくつもある。「何が分離されるか」「Dockerが要るか」「手間はどれくらいか」で比べると選びやすい。

## 基礎文法

| 方式 | 何が分離されるか | Docker要否 | 手間の目安 |
| --- | --- | --- | --- |
| サンドボックス化したBashツール | コマンド実行のファイル・ネットワーク範囲 | 不要 | 小 |
| サンドボックスランタイム | プロセスのファイル・ネットワーク範囲 | 不要 | 小 |
| Devコンテナ | 依存を含む開発環境一式 | 通常必要 | 中 |
| カスタムコンテナ | 自分で定義した環境一式 | 通常必要 | 中〜大 |
| 仮想マシン | OSごと | 不要(別の仮想化ソフトが必要) | 大 |
| クラウドセッション | 手元とは別のクラウド上の環境 | 不要 | 小〜中 |

## つまずきやすい点

- **この表は、出典の比較表を参考にした一般的な整理であり、各方式の最新の仕様と一致しているとは限らない**。具体的な動作や設定は、各ツールの公式ドキュメントで確認が必要
- 「手間の目安」は相対的な傾向で、環境や慣れによって変わる
- 分離すれば絶対に安全になるわけではない。許可した範囲(共有するフォルダやネットワーク)の中では、操作が実行される

## 実装例(コード)

```bash
# コンテナの例: 現在のフォルダだけを共有して、使い捨ての環境でコマンドを実行する
docker run --rm -it -v "$PWD":/work -w /work ubuntu:24.04 bash
```

方式の分類は、公開されていた比較表を参考にした一般的な整理。表の内容は、公式ドキュメントでの確認を前提に参照すること。
